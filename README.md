# dawg-replay

dawg-replay запускает на вашем компьютере скрипты сбора данных: карточки товаров с маркетплейса, цены, объявления, статистику. Скрипты работают через облачные браузеры DAWG, локальный браузер не нужен.

Скрипт пишет кодинг-агент (Claude Code или Codex) со скиллом dawg-replay-builder. Вы описываете задачу словами, агент один раз проходит нужный путь по сайту в браузере DAWG и собирает из него обычный скрипт с параметрами. Скрипт попадает в приложение, и дальше вы запускаете его сами: в веб-интерфейсе меняете параметры, смотрите прогресс и скачиваете результат. Агент снова нужен, только когда сайт поменялся и скрипт пора чинить.

Приложение для клиентов DAWG, которым нужны регулярные выгрузки с сайтов. Читать код не обязательно. Нужны ключ DAWG и Claude Code или Codex, работает на macOS, Windows и Linux. Скрипт запускается без агента, расход только в минутах браузеров DAWG по тарифу.

## Установка

1. Поставьте `uv`, он устанавливает приложение и запускает скрипты: https://docs.astral.sh/uv/getting-started/installation/

   macOS и Linux:

   ```sh
   curl -LsSf https://astral.sh/uv/install.sh | sh
   ```

   Windows (PowerShell):

   ```powershell
   powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
   ```

   После установки откройте новое окно терминала. Python ставить отдельно не нужно, uv скачает его сам.

2. Поставьте приложение:

   ```sh
   uv tool install dawg-replay
   ```

   Проверка:

   ```sh
   dawg-replay --version
   ```

   Если команда не найдена, выполните `uv tool update-shell` и откройте терминал заново.

3. Сохраните ключ DAWG. Ключ выдаётся в личном кабинете https://dawgswarm.ru.

   ```sh
   dawg-replay config set-key
   ```

   Команда спросит ключ и положит его в системное хранилище паролей (Связка ключей на macOS, Диспетчер учётных данных на Windows, Secret Service на Linux). Ключ можно и вставить из буфера: `pbpaste | dawg-replay config set-key` на macOS. Другой способ: откройте интерфейс командой `dawg-replay ui` и введите ключ на экране «Настройки», там же есть кнопка проверки.

## Подключение агента

Агенту нужен скилл dawg-replay-builder и сервер dawg-mcp, через который он открывает браузер DAWG. Оба ставятся одним плагином.

### Claude Code

В сессии Claude Code:

```
/plugin marketplace add dawgswarm/dawg-replay
/plugin install dawg-replay-builder@dawg-replay
```

При установке плагин спросит ключ DAWG и сохранит его в системном хранилище паролей. Проверка: `/mcp` показывает сервер `dawg` в статусе connected.

### Codex

Для Codex скилл копируется в каталог скиллов, а dawg-mcp прописывается в `~/.codex/config.toml`. Пошагово: [README плагина](skill/README.md#codex).

## Первый скрипт

Заведите одну папку для работы с агентом и открывайте агента в ней:

```sh
mkdir -p ~/dawg-scripts
cd ~/dawg-scripts
claude
```

Для Codex вместо `claude` запустите `codex`. Опишите задачу своими словами, например:

> Собери карточки с Ozon по поисковому запросу: название, цена, рейтинг и число отзывов. Запрос и число страниц хочу менять между запусками. Результат в CSV.

Дальше агент:

1. Уточнит, что собирать, что вы будете менять между запусками (это станут параметры) и куда отдавать данные.
2. Пройдёт путь по сайту в облачном браузере DAWG. На это уходит немного минут тарифа.
3. Напишет скрипт в `~/dawg-scripts/<имя>/script.py` и прогонит его на маленьких параметрах, пока прогон не пройдёт.
4. Зарегистрирует скрипт в приложении (`dawg-replay add`) и скажет, как он называется.

После этого скрипт виден в интерфейсе на экране «Скрипты». Черновик в `~/dawg-scripts` можно оставить для будущих правок: у приложения своя копия.

## Работа в интерфейсе

```sh
dawg-replay ui
```

Команда запускает интерфейс на этом компьютере и открывает его в браузере. Окно терминала держите открытым: пока работает команда, работает интерфейс. Остановить: Ctrl+C. Запуски, начатые в интерфейсе, при остановке отменяются.

- Главная. Что идёт сейчас, что требует внимания (последний запуск упал или собрал не всё), последние запуски, быстрый запуск по пресетам и остаток минут.
- Скрипты. Библиотека скриптов с поиском. На карточке скрипта форма параметров, пресеты, история запусков, версии и код для просмотра.
- Запуск. Выберите скрипт, поменяйте параметры и нажмите «Запустить». Сохраните удачный набор параметров как пресет, чтобы запускать его одной кнопкой. У поля даты можно выбрать не конкретную дату, а «вчера», «начало месяца» или «конец прошлого месяца»: такой пресет при каждом запуске, и по расписанию тоже, берёт свою дату, а на экране запуска в «Параметрах запуска» видно, какая дата получилась. Если скрипт работает по таблице (список аккаунтов, товаров, адресов), загрузите в поле файл Excel (`.xlsx`) или CSV: сразу видно имя файла, число строк и первые строки, а ошибки (нет нужной колонки, слишком много строк) видны до запуска. Одну-две строки можно не готовить файлом: «Ввести вручную» открывает таблицу с нужными колонками, у секретной таблицы пароли и коды вводятся скрыто. Таблицу, загруженную или введённую в форму, можно сохранить в пресет; в одном запуске она заменяет таблицу пресета, сам пресет не меняется. На экране запуска видны шаги, прогресс, собранные строки и журнал; кнопка «Отменить» останавливает запуск и закрывает его браузеры.
- Результаты. Файлы, которые сохранил скрипт, появляются на экране запуска с кнопкой «Скачать». «Открыть папку» показывает их в файловом менеджере. Старые запуски доступны из истории скрипта.
- Строки. Если скрипт работает по таблице, на экране запуска есть блок «Строки»: какие строки сделаны, какие упали и почему, фильтр «только упавшие» и отчёт целиком в CSV. В истории и на главной итог вида «48 из 50, 2 упали». Кнопка «Перезапустить упавшие» запускает скрипт заново только для упавших строк и тех, до которых он не дошёл, если запуск оборвался; сделанные строки не повторяются. Секретную таблицу (пароли, коды) приложение хранит для этого только сутки, потом файл нужно загрузить заново.
- Импорт. Если агент работал на другом компьютере или прислал файл, на экране «Скрипты» нажмите «Добавить скрипт» и перетащите `script.py`. Приложение проверит файл и покажет, что будет добавлено, а для новой версии и отличия от текущей.
- Вопросы. Скрипт может спросить посреди запуска: код из SMS, подтверждение перед отправкой, выбор из вариантов. Такой запуск отмечен «ждёт ответа» на главной и в истории скрипта, а на экране запуска появляется поле или кнопки для ответа. Если разрешить уведомления (кнопка под вопросом), браузер сообщит о новом вопросе, даже когда вкладка с приложением в фоне. Код из SMS и другие секретные ответы не сохраняются ни в истории, ни в логах.
- Настройки. Ключ DAWG, лимит одновременных запусков, предел длительности запуска и Telegram: свой бот от @BotFather, чат привязывается одноразовой ссылкой, токен бота хранится в системном хранилище паролей.

Те же действия есть в терминале, например:

```sh
dawg-replay list                                  # скрипты
dawg-replay run ozon-search-cards --set query="кофемолка" --follow
dawg-replay run my-actions --param accounts=@аккаунты.xlsx --follow   # таблица из файла
dawg-replay run my-actions --row accounts email=a@b.ru password=- --follow   # строка руками, «-» спросит пароль скрыто
dawg-replay runs                                  # история запусков
dawg-replay usage                                 # минуты браузеров за 7 дней по скриптам
dawg-replay telegram connect                      # токен бота и привязка чата; ещё test, status, disconnect
dawg-replay answer 20261114-091500-a1b2c3 yes     # ответ на вопрос скрипта; - вводит секрет без отображения
```

`run --follow` сам печатает вопрос скрипта и ждёт ответ в терминале.

Минуты в `usage`, на экране запуска и на странице скрипта примерные: они считаются по событиям запусков. Точный расход и остаток показывает главная, данные приходят из личного кабинета DAWG.

Справка по любой команде: `dawg-replay <команда> --help`.

## Когда скрипт сломался

Сайты меняются, и скрипт, который работал вчера, может упасть. Упавший запуск попадает в блок «Требует внимания» на главной. На экране запуска видна причина: сообщение скрипта или последние строки его вывода.

Бывает, что скрипт не падает, а тихо перестаёт собирать данные: запуск зелёный, но строк ноль или намного меньше обычного. Приложение замечает это и пишет «Похоже, сайт поменялся», если:

- скрипт прислал счётчик (таблицу или полоску прогресса), там 0, и файлов результата нет;
- строк меньше половины медианы последних успешных запусков того же скрипта с тем же пресетом (без пресета: с теми же параметрами). Сравнение начинается, когда таких запусков набралось хотя бы 3 и обычно собирается не меньше 10 строк.

Чтобы починить, нажмите «Починить с агентом» на экране запуска (или на главной, в блоках «Требует внимания» и «С прошлого визита»). Появится готовый текст для агента: какой скрипт и версия, где лежит файл, номер запуска, параметры, причина и последние строки ошибок. Нажмите «Скопировать» и вставьте текст в Claude Code или Codex, открытый в той же папке `~/dawg-scripts`. Ключ DAWG, секреты скрипта и токены в адресах в тексте скрыты. То же в терминале:

```sh
dawg-replay fix-prompt 20261114-091500-a1b2c3          # на macOS: ... | pbcopy
```

Можно и своими словами:

> Скрипт ozon-search-cards упал, запуск 20261114-091500-a1b2c3. Почини.

Номер запуска есть на его экране и в `dawg-replay runs`. Агент прочитает журнал, заново пройдёт проблемное место и зарегистрирует новую версию. Старые версии сохраняются: если новая чем-то хуже, на карточке скрипта в блоке «Версии» сделайте текущей прежнюю.

Блок «С прошлого визита» на главной собирает упавшие и подозрительные запуски, которые закончились, пока вас не было, например плановые ночные. Визитом считается работа с главной без перерывов дольше 30 минут. Момент прошлого визита хранится в файле `ui-state.json` в каталоге данных. Отменённые вами запуски в блок не попадают.

Если на главной появился блок «Возможно, остался браузер», запуск остановился в момент создания браузера. Нажмите «Освободить» у браузеров, которые вы не открывали сами: открытый браузер тратит минуты.

## Регулярные запуски

Приложение ставит регулярный запуск в планировщик системы: cron на macOS и Linux, Планировщик задач на Windows. Своей службы у приложения нет, `dawg-replay ui` держать открытым не нужно. Запуск идёт по пресету, поэтому сначала сохраните пресет с нужными параметрами в форме запуска или командой:

```sh
dawg-replay preset save ozon-search-cards daily --set query="кофемолка" --set max_pages=3
```

В интерфейсе: на странице скрипта блок «Регулярный запуск». Выберите пресет и как часто запускать (каждый день, раз в неделю, каждые несколько часов) и нажмите «Добавить расписание». Ближайшие запуски видны на главной в блоке «По расписанию», а сами запуски в истории помечены «по расписанию».

То же в терминале:

```sh
dawg-replay schedule add ozon-search-cards --preset daily --daily 09:00
dawg-replay schedule add ozon-search-cards --preset daily --weekly пн 09:00
dawg-replay schedule add ozon-search-cards --preset daily --every-hours 6
dawg-replay schedule list                 # расписания, ближайший запуск, есть ли задача в планировщике
dawg-replay schedule remove <id>          # снять
```

`--every-hours` принимает 1, 2, 3, 4, 6, 8 или 12 и считает от полуночи: при 6 запуски в 0:00, 6:00, 12:00 и 18:00. На macOS и Linux есть ещё `--cron "30 9 * * 1-5"` для своего выражения cron. Время местное.

Что ставится в планировщик: полный путь к `dawg-replay` и каталог `uv` в `PATH` (у cron и Планировщика свой короткий `PATH`), команда `dawg-replay run <скрипт> --preset <пресет> --follow --schedule <id>` и вывод в лог `schedules/<id>.log` в [каталоге данных](#где-лежат-данные). В crontab своя строка помечена `# dawg-replay:<id>`, остальные строки приложение не меняет. На Windows задачи лежат в папке `dawg-replay` Планировщика заданий.

`schedule list` сверяет расписания с планировщиком. Если задачу удалили вручную, напротив расписания будет «задача пропала»; если в планировщике осталась задача без расписания в приложении, она показана отдельно и сама ничего не запустит. `dawg-replay schedule sync` ставит пропавшие задачи заново и снимает лишние.

При удалении скрипта или пресета его регулярные запуски снимаются вместе с ним.

Если новая версия скрипта не принимает значение из пресета (например, подняла самую раннюю дату), на странице скрипта у формы и у расписания видно, какое значение и почему. Плановый и быстрый запуск по такому пресету не начинаются, пока пресет не пересохранён: молча подставлять значение по умолчанию опасно, особенно для скриптов, которые что-то меняют на сайте. Ручной запуск из формы идёт со значениями, которые видны в форме.

Плановый запуск, который не смог начаться (например, в пресете нет значения, которое стало обязательным в новой версии скрипта), остаётся в истории скрипта со статусом «не начат» и причиной и попадает в «Требует внимания» на главной. Скрипту с секретной таблицей (логины, пароли) для расписания нужна эта таблица в пресете: загрузите файл в форму и сохраните пресет. Без таблицы в пресете расписание не добавится.

Если в момент планового запуска все места для одновременных запусков заняты (лимит в настройках, по умолчанию 3), запуск встаёт в очередь и ждёт до 30 минут. Ждущие начинают по порядку, в котором встали. На главной они видны в блоке «Ждут свободного слота», оттуда же их можно убрать из очереди. Если за это время место не освободилось, запуск записывается в историю как «пропущен» и попадает в «Требует внимания». Предел ожидания меняется командой `dawg-replay config set wait_slot_minutes 60`. Ручной запуск из интерфейса при занятом лимите получает отказ сразу, а в терминале можно подождать так же, как плановый: `dawg-replay run <скрипт> --wait`.

Ключ DAWG берётся из системного хранилища паролей, поэтому компьютер должен быть включён, а пользователь должен быть в системе. На Linux без графического сеанса хранилище паролей может быть недоступно: проверьте первый запуск по логу. На macOS при первой записи в crontab система может спросить разрешение для терминала.

## Уведомления в Telegram

Приложение само пишет в Telegram о запусках, которые идут без вас: итог, падение, вопрос скрипта. Сообщения отправляет тот процесс, который ведёт запуск (интерфейс, `dawg-replay run` или задача планировщика), поэтому `dawg-replay ui` держать открытым не нужно.

Подключение. Создайте своего бота у @BotFather (`/newbot`) и вставьте токен в Настройках, блок Telegram, или в терминале: `dawg-replay telegram connect`. Приложение покажет ссылку на бота с одноразовым кодом: откройте её и нажмите «Start». Чат привязывается только по этому коду, сообщения из других чатов бот не принимает. Токен хранится в системном хранилище паролей, в настройках только чат и имя бота. Проверка: «Отправить проверочное» или `dawg-replay telegram test`; если отправка не удалась, в блоке Telegram видна последняя ошибка.

О чём писать, выбирается в Настройках (галочки «О чём писать») или командой `dawg-replay telegram set`:

| Событие | Ключ | По умолчанию |
|---|---|---|
| Запуск упал: ошибка, таймаут, не стартовал или пропущен по расписанию | `failed` | да |
| Скрипт задал вопрос | `ask` | да |
| Запуск по расписанию закончился успешно или частично | `done_scheduled` | да |
| Ручной запуск закончился: всегда, если дольше порога или никогда | `done_manual` | если дольше порога |
| Порог долгого ручного запуска, минут | `long_minutes` | 10 |
| Похоже, сайт поменялся (строкой в сообщении об итоге) | `suspicious` | да |
| Приложить главный файл итога документом, до 50 МБ | `attach_main` | нет |

Отмена запуска и черновые запуски агента сообщений не дают.

Правила можно уточнить у скрипта (блок «Уведомления в Telegram» на его странице) и у расписания (в блоке «Регулярный запуск»). Каждое правило там либо наследуется, либо своё; побеждает самое конкретное: запуск, затем расписание, затем скрипт, затем общие настройки. У расписания нет `done_manual` и порога. Для одного запуска на форме есть поле «Сообщить в Telegram, когда закончится» («по настройкам», «всегда», «нет»), в терминале `--notify` и `--no-notify`. Этот выбор касается только сообщения об успешном итоге, о падениях и вопросах Telegram пишет по правилам.

```sh
dawg-replay telegram set                                     # общие правила
dawg-replay telegram set done_manual always                  # о каждом ручном запуске
dawg-replay telegram set long_minutes 30                     # «долгий» с 30 минут
dawg-replay telegram set done_manual never --script my-actions
dawg-replay telegram set done_scheduled off --schedule <id>  # inherit вернёт общее
dawg-replay run ozon-search-cards --set query="кофемолка" --notify
dawg-replay telegram status                                  # подключён ли бот, последняя ошибка
dawg-replay telegram disconnect                              # стереть токен и забыть чат
```

Ответ на вопрос скрипта приходит прямо в Telegram: подтверждение и выбор кнопками, текст ответом на сообщение с вопросом (если вопрос один, подойдёт и простое сообщение). Засчитывается первый ответ, откуда бы он ни пришёл: из Telegram, интерфейса или `dawg-replay answer`. Секретный ответ (код из SMS) бот сразу удаляет из чата, в историю и журнал он не попадает.

Сообщения об итоге начинаются с названия скрипта и пресета, в них строка итога, число записей, ссылки скрипта, длительность и время запуска. Ссылки на экран запуска нет: в конце строка вида «В приложении: Запуски, <скрипт>, <время>». Значения секретов скрываются так же, как в журнале.

Если Telegram недоступен, запуск об этом не знает и идёт как обычно: ошибка видна строкой в журнале запуска и в Настройках, а неотправленный итог досылает следующий запуск приложения или команды (не старше суток, без повторов). Если Telegram у вас открывается не напрямую, укажите свой сервер Bot API или зеркало: `dawg-replay config set telegram_api_url https://...`; системный прокси учитывается.

## Сохранённые входы

Скрипт, который входит в личный кабинет, может запоминать вход между запусками: после успешного входа сохраняются cookies сайта, и в следующий раз входить заново не нужно. Неудачный или прерванный вход не сохраняется. Сохранённые входы видны на странице скрипта в блоке «Сохранённые входы»: имя входа (обычно почта или название кабинета), когда он сохранён и когда использован. Если вход перестал работать или аккаунт больше не нужен, нажмите «Забыть» или «Забыть все»: скрипт войдёт заново при следующем запуске.

То же в терминале:

```sh
dawg-replay logins list ozon-seller
dawg-replay logins forget ozon-seller user@example.com
dawg-replay logins forget ozon-seller --all
```

Входы лежат в каталоге данных в `logins/<скрипт>/`, доступ к ним есть только у вашего пользователя. В историю запусков и логи они не попадают. Удаление скрипта удаляет и его входы.

## Обновление

```sh
uv tool upgrade dawg-replay
```

Скрипты, пресеты и история запусков сохраняются. Плагин Claude Code обновляется командой `/plugin marketplace update dawg-replay`.

## Где лежат данные

Скрипты, их версии, пресеты, история запусков и файлы результатов хранятся в каталоге данных:

| ОС | Каталог |
|---|---|
| macOS | `~/Library/Application Support/dawg-replay` |
| Windows | `C:\Users\<имя>\AppData\Local\dawg-replay` |
| Linux | `~/.local/share/dawg-replay` (или `$XDG_DATA_HOME/dawg-replay`) |

Точный путь покажет `dawg-replay config show`. Файлы результатов лежат в `runs/<номер запуска>/output/`. Другой каталог можно задать переменной окружения `DAWG_REPLAY_HOME`.

Таблицы, загруженные в форму, лежат в `uploads/` сутки, затем удаляются. Таблица, которую скрипт считает секретной (логины, пароли), в историю запусков и логи не попадает. Если сохранить её в пресете, она лежит отдельным файлом в `preset-tables/` (доступ только у вашего пользователя), в интерфейсе видны только имя файла и число строк; файл удаляется вместе с пресетом или скриптом. Таблица, загруженная в форму на один запуск, пресет не меняет.

Сохранённые входы скриптов лежат в `logins/` (см. [Сохранённые входы](#сохранённые-входы)): это cookies сайтов, берегите каталог данных так же, как браузерный профиль.

Ключ DAWG и секреты скриптов (например, токен таблицы) в каталог данных не попадают, они хранятся в системном хранилище паролей под именем `dawg-replay`.

## Удаление

Сначала снимите регулярные запуски, иначе задачи останутся в планировщике: `dawg-replay schedule list`, затем `dawg-replay schedule remove <id>` для каждого. Потом удалите приложение:

```sh
uv tool uninstall dawg-replay
```

Затем удалите каталог данных из таблицы выше, если история и скрипты больше не нужны. Ключ DAWG и секреты скриптов уберите из хранилища паролей: это записи с `dawg-replay` в имени в приложении «Связка ключей» (macOS), в Диспетчере учётных данных (Windows) или в менеджере паролей Linux, например Seahorse. Плагин Claude Code удаляется командой `/plugin uninstall dawg-replay-builder@dawg-replay`.

## Безопасность

Скрипт это обычная программа на Python. Она запускается на вашем компьютере с вашими правами и вашим ключом DAWG, песочницы нет. Добавляйте скрипты, которые собрал ваш агент или прислал человек, которому вы доверяете. Перед добавлением файла через интерфейс посмотрите его карточку: какие пакеты он поставит и что изменилось в коде.

Интерфейс слушает только этот компьютер (127.0.0.1) и открывается по ссылке с токеном, который действует, пока работает `dawg-replay ui`. Другие сайты, открытые в браузере, обратиться к интерфейсу не могут.
