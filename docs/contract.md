# Контракт скрипта dawg-replay, версия 1.3

Документ описывает, как устроен скрипт, который запускает приложение `dawg-replay`. Его же читает скилл `dawg-replay-builder`. Протокол состоит из файлов и JSON Lines, поэтому скрипт может выполнять его и без `dawg-replay-kit`.

Версия контракта задаётся в манифесте полем `contract`. Скрипт с мажорной версией, которую приложение не знает, не запускается, приложение пишет почему. Поддерживаемые версии показывает `dawg-replay --version`.

Изменения контракта:

- минорная версия: старое приложение может безопасно показать новое как сырую строку (например, новый тип события);
- мажорная версия: всё остальное.

Скрипт указывает в `contract` ту минорную версию, возможности которой использует. Скрипты с `contract = 1` остаются валидными в любой версии 1.N. Поле манифеста из минорной версии новее указанной считается ошибкой с подсказкой, какую версию указать: `site` при `contract = 1` не проходит, нужно `contract = "1.1"`. Так по `contract` видно, какая версия приложения нужна скрипту. Если в скрипте с минорной версией новее известной приложению есть незнакомое поле, приложение (начиная с 1.1) пишет, что скрипт написан под более новый контракт и dawg-replay нужно обновить. Полные версии, которые понимает приложение, показывает `dawg-replay --version --json` в поле `contract_versions`.

| Версия | Что добавлено |
|---|---|
| 1.0 | первая версия |
| 1.1 | необязательные поля манифеста `site` и `tags` (раздел 1.1) |
| 1.2 | типы параметров `date` и `table` (разделы 2.2 и 2.4), сохранённый вход `kit.browser(login=...)` (раздел 6.1), вопрос посреди запуска `kit.ask` и события `ask`, `ask_closed`, переменная `DAWG_SCRIPT_ANSWERS_DIR` (раздел 8) |
| 1.3 | подписи вариантов `{ value, title }` у `enum`, типы `multi_enum`, `time`, `datetime`, поле `min_items`, относительные даты `today-1`, `month_start` и другие в `default` и пресетах (разделы 2.2 и 2.5); в `result` необязательные `count`, `links`, `main`, превью картинок и PDF из `artifact` (раздел 4.2); у `table` поля `input`, `sheet`, `column_types` и файлы TSV и JSON (раздел 2.4); тип `file` и секретный файл (раздел 2.6) |

## 1. Форма скрипта

Скрипт состоит из одного файла `script.py`. В начале файла два блока комментариев в формате [PEP 723](https://peps.python.org/pep-0723/):

1. `script`: стандартный блок с `requires-python` и `dependencies`. Скрипт запускается через `uv run script.py`, uv сам ставит зависимости в изолированное окружение.
2. `dawg-script`: манифест в TOML.

```python
# /// script
# requires-python = ">=3.10"
# dependencies = ["dawg-replay-kit>=1.1,<2", "dawg-sdk-python>=0.4,<0.5", "playwright>=1.58,<2"]
# ///

# /// dawg-script
# contract = "1.1"
# name = "ozon-search-cards"
# title = "Ozon: карточки по поисковому запросу"
# description = "Обходит выдачу Ozon по запросу и собирает название, цену, рейтинг и продавца."
# site = "Ozon"
# tags = ["Цены", "Карточки"]
# version = 3
# timeout_minutes = 60
#
# [[params]]
# name = "query"
# type = "string"
# title = "Поисковый запрос"
# required = true
#
# [[params]]
# name = "max_pages"
# type = "int"
# title = "Сколько страниц выдачи обойти"
# default = 5
# min = 1
# max = 100
#
# [[params]]
# name = "sheet_token"
# type = "secret"
# title = "Токен Google Sheets"
# ///
```

Манифест читается статически: скрипт не запускается, его зависимости не ставятся. Проверить файл: `dawg-replay validate script.py`.

Правила блоков (как в PEP 723):

- блок открывается строкой `# /// <тип>` и закрывается строкой `# ///`;
- каждая строка внутри начинается с `# ` или состоит из одного `#`;
- каждый тип блока встречается в файле один раз;
- блоки разделяются пустой строкой или кодом.

### 1.1 Поля манифеста

| Поле | Тип | Обязательно | Правила |
|---|---|---|---|
| `contract` | целое или строка | да | `1` (то же, что `"1.0"`) или `"1.N"`, где `N` минорная версия |
| `name` | строка | да | slug: строчные латинские буквы, цифры и `-`, до 64 символов. Уникален в приложении, регистрация с тем же `name` создаёт новую версию |
| `title` | строка | да | непустая, показывается в списке скриптов |
| `description` | строка | нет | |
| `site` | строка | нет, с 1.1 | название сайта для людей: `"Ozon"`, `"Wildberries"`, `"Яндекс Маркет"`. Непустая, в одну строку, до 40 символов |
| `tags` | массив строк | нет, с 1.1 | метки для библиотеки скриптов, например `["Цены"]`. До 5 меток, каждая непустая, в одну строку, до 24 символов, без повторов |
| `version` | целое | да | не меньше 1, растёт при каждой правке |
| `timeout_minutes` | целое | нет | не меньше 1, по умолчанию 60. Верхний предел задаётся в настройках приложения |
| `params` | массив таблиц `[[params]]` | нет | см. раздел 2 |

Неизвестное поле считается ошибкой. Так опечатка вроде `timout_minutes` не проходит молча.

## 2. Параметры

Каждый параметр описывается таблицей `[[params]]`.

### 2.1 Общие поля

| Поле | Обязательно | Правила |
|---|---|---|
| `name` | да | строчные латинские буквы, цифры и `_`, первая буква. Уникально в скрипте. Имена `params` и `help` заняты |
| `type` | да | один из типов в 2.2 |
| `title` | да | непустая строка, подпись поля в форме |
| `description` | нет | строка, подсказка к полю |
| `required` | нет | `true` или `false`, по умолчанию `false` |
| `default` | нет | значение того же типа, проходит те же проверки, что и значение при запуске |

Дополнительные поля: `min` и `max` у `int`, `float`, `date`, `time` и `datetime`, `max_items` у списков и `multi_enum`, `min_items` у `multi_enum`, `choices` у `enum` и `multi_enum`, `columns`, `max_rows`, `secret`, а с 1.3 `input`, `sheet` и `column_types` у `table`. У других типов эти поля считаются ошибкой, неизвестные поля тоже.

Пустое значение считается незаданным: у `string`, `text`, `url`, `secret`, `enum`, `date`, `time`, `datetime` строка из одних пробелов, у `url_list`, `string_list`, `multi_enum` и `table` пустой список. Тогда берётся `default`; обязательный параметр без `default` даёт ошибку до запуска, у необязательного значения нет.

Имя параметра используется в трёх местах: ключ в JSON параметров, аргумент автономного режима (`max_pages` даёт `--max-pages`), переменная секрета (`sheet_token` даёт `DAWG_SECRET_SHEET_TOKEN`).

### 2.2 Типы

| `type` | Значение в JSON | Поля | Проверка |
|---|---|---|---|
| `string` | строка | | без перевода строки |
| `text` | строка | | многострочный текст |
| `int` | целое | `min?`, `max?` (целые) | `true`/`false` не считаются числом |
| `float` | число | `min?`, `max?` | целое тоже подходит |
| `bool` | `true`/`false` | | |
| `enum` | строка | `choices` (обязательно) | значение из `choices` |
| `multi_enum` (с 1.3) | список строк | `choices` (обязательно), `min_items?`, `max_items?` | каждое значение из `choices`, без повторов |
| `url` | строка | | адрес `http://` или `https://` с хостом |
| `url_list` | список строк | `max_items?` | каждый элемент как `url` |
| `string_list` | список строк | `max_items?` | |
| `secret` | строка | | `default` запрещён |
| `date` (с 1.2) | строка `ГГГГ-ММ-ДД` | `min?`, `max?` (даты в том же виде) | существующая дата |
| `table` (с 1.2) | список строк таблицы | `columns?`, `max_rows?`, `secret?`, с 1.3 `input?`, `sheet?`, `column_types?` | раздел 2.4, `default` запрещён |
| `time` (с 1.3) | строка `ЧЧ:ММ` | `min?`, `max?` (в том же виде) | от `00:00` до `23:59` |
| `datetime` (с 1.3) | строка `ГГГГ-ММ-ДДTЧЧ:ММ`, местное время | `min?`, `max?` (в том же виде) | существующая дата |
| `file` (с 1.3) | `{path, name, size}`, при `multiple` список таких | `accept?`, `max_mb?`, `multiple?`, `max_items?` (только с `multiple`), `secret?` | раздел 2.6, `default` запрещён |

`min` не больше `max`. `max_items` и `min_items` целые, не меньше 1, `min_items` не больше `max_items`. Типы `date` и `table` требуют `contract = "1.2"`, `time`, `datetime`, `multi_enum`, подписи вариантов, `min_items` относительная дата в `default` и тип `file` требуют `contract = "1.3"`; при меньшей версии манифест не проходит с подсказкой.

`choices` у `enum` и `multi_enum`: непустой список вариантов без повторов значений. Вариант это непустая строка (подпись совпадает со значением) или, с 1.3, таблица `{ value = "price", title = "Сначала дешевле" }`: форма показывает `title`, скрипт, пресеты и CLI работают с `value`. Строки и таблицы можно смешивать.

```toml
[[params]]
name = "stores"
type = "multi_enum"
title = "Склады"
choices = [{ value = "msk", title = "Москва" }, { value = "kzn", title = "Казань" }]
min_items = 1
default = ["msk"]
```

### 2.3 Секреты

Значение `secret` хранится в системном keyring. В пресеты, `params.json` запуска и логи оно не попадает, в UI маскируется. Скрипт получает его в JSON параметров вместе с остальными значениями. Kit заменяет значения секретов на `***` во всех событиях, которые через него проходят.

### 2.4 Таблицы

Параметр `table` приходит из файла CSV, XLSX, а с 1.3 ещё TSV или JSON, из пресета или вводом строк вручную. Файл разбирает приложение (или kit в автономном режиме), скрипт получает готовые строки и файл не читает.

```toml
[[params]]
name = "accounts"
type = "table"
title = "Аккаунты"
required = true
columns = ["email", "Сумма"]
max_rows = 500
```

| Поле | Правила |
|---|---|
| `columns` | список колонок, которые обязаны быть в шапке. Непустые разные названия без пробелов по краям, `_row` занято |
| `max_rows` | целое не меньше 1, по умолчанию 10000 |
| `secret` | `true`: таблица целиком секрет (логины, пароли). По умолчанию `false` |
| `input` (с 1.3) | как человек задаёт таблицу: подмножество `["file", "manual", "preset"]` (файл, ввод вручную, таблица из пресета). По умолчанию все три. Нужен `file` или `manual`. Форма и CLI показывают только объявленное; без `preset` таблица не сохраняется в пресет и скрипт не запускается по расписанию |
| `sheet` (с 1.3) | лист XLSX: имя (`"Заказы"`) или номер с 1. Без поля первый лист; если листов несколько, форма после загрузки предлагает выбрать |
| `column_types` (с 1.3) | типы колонок: `{ qty = "int", price = "float", paid = "bool", day = "date", "Комментарий" = "string" }`. Значения приводятся при загрузке, пустая ячейка типизированной колонки это `null`. Без поля все значения строки |

Разбор файла:

- первая непустая строка шапка, пустые строки пропускаются; у XLSX лист из `sheet`, без него первый;
- TSV (с 1.3) как CSV с табуляцией; JSON (с 1.3) это список объектов: колонки по ключам в порядке появления, вложенные значения не принимаются, `_row` это номер объекта плюс 1;
- значения ячеек строками: дата даёт `ГГГГ-ММ-ДД`, дата со временем `ГГГГ-ММ-ДД ЧЧ:ММ`, целое число пишется без `.0`, пустая ячейка `""`, пробелы по краям убираются;
- CSV в UTF-8 с BOM или без, запасной вариант Windows-1251; разделитель `,` или `;` определяется по шапке;
- ошибка, если в шапке пустое название колонки или повтор, если в строке больше значений, чем колонок в шапке;
- с `column_types` значения колонок приводятся: `int` целое (пробелы между разрядами допустимы), `float` число (запятая или точка), `bool` `true`/`false`, `да`/`нет`, `1`/`0`, `yes`/`no`, `date` `ГГГГ-ММ-ДД` или `ДД.ММ.ГГГГ` (в значении всегда `ГГГГ-ММ-ДД`). Неподходящее значение даёт ошибку до запуска: «строка 4, колонка «qty»: ожидается целое число, получено «x»».

Значение в JSON параметров: список объектов, ключи из шапки, плюс `_row` с номером строки в исходном файле (шапка это строка 1, пропущенные пустые строки тоже считаются). По `_row` человек находит строку в своём файле.

```json
{"accounts": [{"email": "a@example.ru", "Сумма": "100", "_row": 2}, {"email": "b@example.ru", "Сумма": "250", "_row": 4}]}
```

Проверка до запуска: в таблице есть строки, их не больше `max_rows`, в шапке есть все `columns`, и в каждой строке их значения не пустые (ошибка называет номер строки и колонку). Правило одно для файла, ввода вручную, `--row` и автономного режима; колонки, которые бывают пустыми, в `columns` не перечисляются. Ошибки видны в форме сразу после загрузки файла.

Пресет хранит разобранную таблицу и имя файла. Таблица с `secret = true` хранится в пресете отдельным файлом (`<данные приложения>/preset-tables/<script>/`, каталог 0700, файл 0600), в базе у пресета только ссылка, имя файла и число строк; поэтому запуск по расписанию с таким пресетом работает. В историю запусков, логи и текст для починки она не попадает: скрипт получает её как секрет (файл параметров во временном каталоге 0700, раздел 2.3), в интерфейсе видны только имя файла и число строк. Таблица, загруженная в форму или через `--param`, перекрывает таблицу пресета в этом запуске, сам пресет не меняется, пока его не сохранят заново. Удаление пресета или скрипта удаляет файл таблицы. Kit заменяет на `***` значения её ячеек от 4 символов: короткие значения вроде `1` или `да` встречаются в выводе повсюду, их маскировка испортила бы весь лог.

В приложении таблица задаётся загрузкой файла в форме или в CLI: `--param accounts=@путь/к/файлу.xlsx` (то же, что `--set`). Несколько строк можно ввести и руками: «Ввести вручную» в форме (колонки из `columns`, без них человек задаёт их сам) или `--row accounts email=a@b.ru password=-` в CLI (повторяемый, `-` спрашивает значение без отображения). Значение для скрипта то же: список строк с `_row` 2, 3, … Поэтому `columns` стоит перечислять полностью: по ним строится ввод вручную.

### 2.5 Относительные даты (с 1.3)

У `date` и `datetime` в `default` и в пресете вместо даты можно хранить выражение. Оно вычисляется в момент запуска по местному времени компьютера, плановый запуск тоже; скрипт получает готовую дату, в истории запуска видна фактическая дата.

| Выражение | Что значит |
|---|---|
| `today`, `today-1`, `today+7` | сегодня, вчера, через неделю (число дней любое) |
| `week_start` | понедельник этой недели |
| `month_start`, `month_end` | первый и последний день этого месяца |
| `prev_month_start`, `prev_month_end` | первый и последний день прошлого месяца |

К любому основанию можно прибавить дни: `month_start+14`, `week_start-7`. У `datetime` после выражения может стоять время: `today-1T09:00`, без него 00:00. `min` и `max` задаются точными датами и проверяются после вычисления: выражение, которое в день запуска выходит за пределы, даёт ошибку до старта. В форме у поля даты выбор «точная дата» или выражение с подсказкой, во что оно превращается сегодня; в CLI и автономном режиме выражение передаётся как значение: `--set since=today-1`, `--since month_start`.

### 2.6 Файлы (с 1.3)

```toml
[[params]]
name = "invoice"
type = "file"
title = "Счёт"
accept = [".pdf", "image/*"]
max_mb = 10

[[params]]
name = "key"
type = "file"
title = "Ключ сервиса"
secret = true
```

```python
with open(kit.params.invoice["path"], "rb") as f:   # {"path", "name", "size"}
    ...
```

- Значение: `{"path": абсолютный путь к копии, "name": имя исходного файла, "size": байт}`, у `multiple = true` список таких (`max_items` ограничивает число файлов). Скрипт читает файл по `path` и не должен его менять: это копия только для этого запуска.
- `accept`: расширения с точкой (`".pdf"`) или типы (`"application/pdf"`, `"image/*"`; тип определяется по расширению имени). `max_mb`: предел размера одного файла, по умолчанию 25, не больше 1024.
- В приложении файл загружается в форме (кнопка у поля, проверка сразу) или в CLI: `--param invoice=@путь/к/файлу`, для `multiple` повтором `--param`. Пресет хранит копию файла, поэтому исходник можно удалить; файл, загруженный в форму при открытом пресете, заменяет файл пресета только на этот запуск.
- Обычный файл копируется в каталог запуска (`input/<имя параметра>/`), в истории запуска видны имя, размер и путь к этой копии.
- `secret = true` (ключ сервиса, сертификат): копия лежит во временном каталоге секретов (0700, файл 0600) только на время запуска и удаляется после выхода процесса. В истории запуска, логах и тексте для агента видно только имя файла; в пресете файл хранится отдельно (0600) и виден только его имя.
- Автономный режим: `--invoice путь` (у `multiple` несколько путей через пробел), kit сам собирает `{path, name, size}`.


## 3. Окружение запуска

Приложение запускает `uv run script.py` отдельным процессом и передаёт переменные:

| Переменная | Значение |
|---|---|
| `DAWG_API_KEY` | ключ из настроек приложения |
| `DAWG_BASE_URL` | если задан в настройках |
| `DAWG_SCRIPT_PARAMS` | путь к JSON с проверенными значениями параметров, секреты подставлены |
| `DAWG_SCRIPT_EVENTS` | путь к файлу событий (JSON Lines), скрипт пишет туда |
| `DAWG_SCRIPT_OUTPUT_DIR` | каталог этого запуска для выходных файлов |
| `DAWG_SCRIPT_RUN_ID` | id запуска |
| `DAWG_SCRIPT_STOP_FILE` | путь к файлу, который приложение создаёт при отмене (раздел 7). Kit следит за ним сам |
| `DAWG_SCRIPT_LOGINS_DIR` | каталог сохранённых входов скрипта (раздел 6.1), с контракта 1.2 |
| `DAWG_SCRIPT_ANSWERS_DIR` | каталог, куда приложение пишет ответы на вопросы скрипта (раздел 8) |

JSON параметров: объект, ключи которого совпадают с `name` параметров. Необязательный параметр без значения и без `default` в нём отсутствует.

stdout и stderr процесса приложение сохраняет как сырой лог. События в stdout не пишутся, поэтому `print` в скрипте протокол не ломает.

### 3.1 Автономный режим

Если переменных `DAWG_SCRIPT_*` нет (скрипт запущен руками):

- параметры берутся из `--params file.json` или из аргументов вида `--max-pages 3`, для остальных берётся `default`;
- секреты читаются из переменных `DAWG_SECRET_<ИМЯ_ПАРАМЕТРА>`, keyring не используется;
- если обязательный параметр не задан, скрипт завершается и пишет, какого аргумента не хватает;
- события печатаются в stderr в читаемом виде, файлы пишутся в `./output/`, сохранённые входы в `./logins/`;
- ключ берётся из `DAWG_API_KEY`.

Аргументы автономного режима:

- имя аргумента получается из имени параметра: `max_pages` даёт `--max-pages`;
- `bool` принимает `true`/`false` (`--headless false`);
- списки перечисляются через пробел или повторением аргумента: `--urls https://a.ru https://b.ru --urls https://c.ru`;
- значения из аргументов перекрывают значения из `--params`;
- `date` принимает дату `ГГГГ-ММ-ДД` или выражение (раздел 2.5): `--since 2026-11-01`, `--since today-1`; `time` время `--at 09:30`, `datetime` дату и время `--moment 2026-11-20T18:00`;
- `multi_enum` повторением или через запятую: `--stores msk --stores kzn` или `--stores msk,kzn`;
- `table` принимает путь к файлу: `--accounts accounts.csv`, `accounts.xlsx`, с 1.3 ещё `.tsv` и `.json`; лист и типы колонок берутся из `sheet` и `column_types`. Для XLSX kit нужен пакет `openpyxl` в `dependencies` скрипта, без него kit пишет, что добавить. CSV читается без него;
- у секретов нет аргумента, в файле `--params` они тоже не принимаются;
- `--help` показывает все аргументы и переменные секретов.

Если манифест или параметры не подходят, скрипт завершается с кодом 2 и пишет все найденные ошибки в stderr. В режиме приложения та же причина попадает в файл событий как `log` с уровнем `error`.

## 4. События

Каждая строка файла событий содержит JSON-объект с полями `t` (тип), `ts` (время в ISO 8601) и полями конкретного типа. Типы ниже это всё, что умеет показывать приложение. Данные любой задачи подгоняются под них.

| `t` | Поля | Как показывается |
|---|---|---|
| `log` | `level` (`debug`/`info`/`warn`/`error`), `msg` | строка в ленте лога, цвет и фильтр по уровню |
| `stage` | `name` | текущий шаг в шапке запуска и отметка на таймлайне |
| `progress` | `id`, `label`, `done`, `total?` | полоска прогресса; без `total` счётчик. Каждый `id` даёт свою полоску, новое значение заменяет старое |
| `metric` | `key`, `label`, `value` (число или строка), `unit?` | плитка с подписью и значением, новое значение заменяет старое |
| `rows` | `table`, `columns?`, `rows` (список объектов) | превью таблицы, до 500 строк на таблицу. Полные данные скрипт сохраняет сам |
| `artifact` | `path` (внутри output dir), `label`, `mime?` | файл в блоке «Результаты»: скачать или открыть папку |
| `item` | `key` (строка или число), `status` (`ok`/`failed`/`skipped`), `msg?`, `row?` (значение `_row` строки таблицы) | отчёт по строкам входа, с контракта 1.2 (раздел 4.1) |
| `session` | `action` (`provisioning`/`open`/`close`/`failed`), `session_id` (у `open` и `close`), `browser_id?` | учёт браузеров запуска (раздел 6), в UI счётчик открытых браузеров |
| `result` | `status` (`ok`/`partial`/`failed`), `summary` (короткий текст, markdown), `count?`, `links?`, `main?` (раздел 4.2) | итоговая карточка запуска |
| `ask` | `id`, `question`, `kind` (`text`/`confirm`/`choice`), `choices?`, `secret`, `deadline` | вопрос человеку с полем или кнопками, отметка «ждёт ответа» (раздел 8) |
| `ask_closed` | `id`, `outcome` (`answered`/`timeout`), `answer?` (только у несекретного) | вопрос закрыт, строка в журнале |

Правила:

- неизвестный `t` или битая строка показываются в логе как сырая строка с пометкой;
- итог запуска определяют код выхода и последнее событие `result`. Выход 0 без `result` считается `ok`. Ненулевой выход всегда даёт `failed`, даже если был `result: ok`;
- kit прореживает `progress` и `metric` (не чаще 4 раз в секунду на `id`), их можно вызывать в цикле.

### 4.1 Отчёт по строкам (с контракта 1.2)

```python
for row in kit.params["accounts"]:
    try:
        ...
        kit.item(row["email"], "ok", row=row["_row"])
    except Exception as e:
        kit.item(row["email"], "failed", str(e), row=row["_row"])
```

- `kit.item(key, status, msg=None, row=None)` пишет итог по одной строке: `ok` сделана, `failed` упала, `skipped` пропущена (например, уже была сделана в прошлый раз). Повторный `item` той же строки заменяет прежний: строка это `row`, если он передан, иначе `key` (`1` и `"1"` один ключ). `msg` длиннее 1000 символов обрезается.
- Экран запуска: блок «Строки» со счётчиками по статусам и таблицей ключ, статус, сообщение, фильтр «только упавшие», отчёт целиком в CSV. В списках запусков и на главной итог вида «48 из 50, 2 упали».
- Детектор тихой поломки считает сделанными строки `ok` и `skipped` и сравнивает их с прошлыми успешными запусками, как строки `rows`. `count` из `result` (раздел 4.2) важнее.
- Ключ и сообщение маскируются так же, как остальные события: у таблицы с `secret = true` ключ из её значений придёт как `***`. Строки при этом не сливаются, если передан `row`; без `row` у секретной таблицы ключом берите номер строки.
- «Перезапустить упавшие» на экране запуска: доступно, когда у скрипта ровно один параметр `table` и в `item` есть `row`. Новый запуск получает ту же таблицу, отфильтрованную до строк с `failed`, а если запуск оборвался (итог `failed`), ещё и до строк без `item`. Остальные параметры те же, пресет не ставится. Секретная таблица берётся из загрузки, по которой запускали, пока она хранится (сутки), иначе приложение просит загрузить файл заново.

### 4.2 Итог и файлы результата (с контракта 1.3)

```python
kit.artifact(shot, "Скриншот: заявка отправлена", "image/png")
kit.result("ok", "собрано 120 карточек", count=120, main="cards.xlsx",
           links=[{"title": "Таблица клиента", "url": "https://docs.google.com/..."}])
```

- `count`: сколько записей или строк собрано, целое не меньше 0. Детектор тихой поломки берёт его первым, раньше `item`, `rows` и `progress`; `count=0` считается пустым итогом, даже если файл (например, CSV с одной шапкой) сохранён.
- `links`: список `{"title": ..., "url": ...}`, адреса только `http://` и `https://`, показываются ссылками в итоговой карточке (до 20).
- `main`: путь главного файла внутри output dir, как у `artifact`. На экране запуска кнопка «Открыть результат» первой. Файл объявляется и через `artifact`, `main` только выбирает главный.
- Kit проверяет поля и бросает `ValueError` на неподходящих; приложение молча отбрасывает то, что не прошло проверку, итог от этого не теряется.
- Превью: `artifact` с `mime` `image/png`, `image/jpeg`, `image/gif`, `image/webp` показывается миниатюрой с открытием в полный размер, `application/pdf` открывается во встроенном просмотрщике браузера. Остальное, в том числе SVG и HTML, только скачивается. Отдаются только файлы, объявленные через `artifact`, из каталога этого запуска.
- «Скачать всё архивом» отдаёт zip каталога output целиком (без символических ссылок).

## 5. Данные

Куда уходят данные, решает скрипт: CSV или JSON в output dir, Google-таблица, база, бот. Приложение данные не разбирает, оно показывает превью из `rows` и файлы из `artifact`. При падении на середине скрипт сохраняет уже собранное и отдаёт `result: partial`.

## 6. Браузеры DAWG

```python
with kit.browser(geo="moskva") as b:        # или async with
    b.page.goto("https://www.ozon.ru")
```

- Скрипт получает браузер через `kit.browser(proxy=None, geo=None, ready_timeout=120)`: облачный Chromium DAWG и Playwright по CDP. Внутри доступны `.page`, `.context`, `.browser`, `.session_id`. `geo` принимает slug города или координаты `"55.75,37.61"`.
- Kit создаёт браузер по REST (`POST /api/v1/browsers`, затем ожидание готовности), освобождает через `release(session_id)` из `dawg-sdk-python`. Браузер освобождается по `session_id`, `browser_id` нужен только для отображения.
- Порядок событий `session`:
  - `provisioning` до запроса на создание;
  - `open` с `session_id` сразу после ответа на создание, до ожидания готовности;
  - `close` после освобождения, когда сессии нет в списке сессий ключа;
  - `failed`, если платформа ответила ошибкой и браузер точно не создан. Закрывает `provisioning`.
- Kit освобождает браузер при выходе из `with`, при исключении, по сигналу отмены и при выходе из процесса. Если освобождение не подтвердилось, `close` не пишется, браузер освобождает приложение.
- После завершения процесса с любым исходом приложение освобождает все `session_id` с событием `open` без `close`.
- Если есть `provisioning` без `open` и без `failed`, id браузера неизвестен. Приложение показывает предупреждение «возможно, остался браузер» со списком сессий ключа, созданных в этом окне, и даёт освободить их вручную. Сессии ключа приложение само не освобождает: на нём живут `dawg-mcp` и другие запуски.
- Итог страховки дописывается в `events.jsonl` с полем `source = "dawg-replay"`: `session close` за каждый освобождённый браузер и строки `log`. Подробности в `insurance.json` каталога запуска (`released`, `failed`, `suspects`). Повторная страховка того же запуска ничего не делает.
- Если платформа отказала в браузере из-за лимита тарифа (HTTP 429), kit повторяет запрос до 3 раз с паузой `retry_after` (не больше 60 с), потом бросает `BrowserLimitError` с сообщением «достигнут лимит одновременных браузеров тарифа».
- Сколько браузеров одновременно держит скрипт, задаётся явно: `kit.set_browser_limit(n)`, по умолчанию 1. Попытка открыть больше сразу даёт `BrowserLimitReached`.
- Kit маскирует ключ DAWG (`DAWG_API_KEY`) в событиях так же, как секреты.

### 6.1 Сохранённый вход (с контракта 1.2)

```python
with kit.browser(login=row["email"]) as b:   # или login="кабинет"
    b.page.goto("https://seller.example.ru/")
    if not logged_in(b.page):                  # проверку пишет скрипт
        log_in(b.page, row["email"], row["password"])
        b.save_login()                         # вход удался: сохранить
```

- `login` это имя входа: почта, телефон или любое название, до 200 символов. Перед работой kit загружает в контекст браузера сохранённые cookies и localStorage этого входа. Загрузка не ходит на сайт: localStorage ставится на пустой странице с перехваченными запросами.
- Залогинен ли браузер, kit не знает: сайт мог отозвать сессию, вход мог не удаться, запуск мог быть отменён до отправки формы. Поэтому новый вход появляется только по `b.save_login()`, который скрипт зовёт сразу после успешного входа (в `async with`: `await b.save_login()`). Возвращает `True`, если сохранил; ошибку пишет в лог как `warn`. Сохранённый так вход не теряется, даже если процесс убьют жёстко.
- При закрытии браузера, в том числе по отмене, kit обновляет cookies и localStorage входа, который уже есть: восстановленного (`b.login_restored`) или сохранённого в этом браузере через `b.save_login()`. Вход, которого не было, при закрытии не создаётся: kit пишет `log` «вход не сохранён: скрипт не подтвердил его». Так в «Сохранённых входах» не появляется аккаунт с неверным паролем или вход, прерванный на вопросе с кодом.
- `b.forget_login()` стирает сохранённый вход (например, аккаунт заблокирован, пароль сменился, повторный вход после устаревшей сессии не удался). После него при закрытии браузера ничего не сохраняется; `b.save_login()` снова сохраняет и включает обновление при закрытии.
- Не загрузился или не сохранился вход: kit пишет `log` с уровнем `warn` и продолжает, скрипт падать не должен. При отмене посреди загрузки прежний вход не перезаписывается.
- Хранение: каталог из `DAWG_SCRIPT_LOGINS_DIR` (`<данные приложения>/logins/<script>/`), в автономном режиме `./logins/`. Каталог 0700, файл на вход 0600, имя файла это хеш имени входа, само имя лежит внутри файла. Входы не попадают в историю запусков, события, логи и экспорт.
- Пользователь видит входы на странице скрипта («Сохранённые входы»: имя, когда сохранён и использован, «Забыть», «Забыть все») и в CLI: `dawg-replay logins list <script>`, `dawg-replay logins forget <script> [<name>|--all]`. Удаление скрипта удаляет его входы.
- Пароли и коды входа в сохранённый вход не пишутся: их скрипт получает через параметры `secret` или таблицу с `secret = true`.

## 7. Отмена и таймаут

- Отмена: приложение создаёт файл `DAWG_SCRIPT_STOP_FILE` и на macOS и Linux шлёт SIGTERM корню дерева процессов (`uv run` передаёт его скрипту и ждёт его). Остальные процессы скрипта (драйвер Playwright и запущенные им самим) сигнал не получают и работают, пока скрипт закрывает браузеры и обновляет уже существующие входы (новый вход при отмене не создаётся, раздел 6.1). После выхода скрипта, или через 15 секунд, если он не вышел, всё дерево процессов убивается. Затем освобождение браузеров по разделу 6. На Windows сигнал не шлётся: CTRL_BREAK завершил бы `uv run` вместе со скриптом без уборки, поэтому там отмену видит только kit по файлу. Скрипт без kit на Windows мягко не останавливается.
- Превышение `timeout_minutes` запускает ту же процедуру, статус запуска `failed (timeout)`.
- Kit при инициализации ставит обработчик SIGTERM (на Windows ещё CTRL_BREAK) и поток, который раз в 0,2 секунды проверяет файл остановки. Появление файла будит главный поток так же, как сигнал, в том числе из `time.sleep`. Сигнал или файл превращается в `SystemExit(143)`, поэтому срабатывают `finally`, контекстные менеджеры и `atexit`, а отложенные события дописываются в файл. Обработчик срабатывает один раз: повторный сигнал (от `uv run` или руками) не прерывает уборку. Если скрипт поставил свой обработчик до kit, kit его не трогает. Ненулевой код выхода после отмены даёт `failed`. Последней строкой kit пишет `log` уровня `warn`: «запуск остановлен приложением (отмена или таймаут)», при ручном запуске «запуск остановлен сигналом». Причину kit не знает, её ставит приложение в итоге запуска.

## 8. Вопрос посреди запуска

С версии 1.2. Скрипт спрашивает человека и ждёт ответа: код из SMS, подтверждение перед действием, выбор из вариантов.

```python
code = kit.ask("Код из SMS на номер ***-12", kind="text", secret=True, timeout_minutes=10)
ok = kit.ask("Отправить 12 заявок?", kind="confirm")        # True или False
city = kit.ask("Какой склад?", kind="choice", choices=["Москва", "Казань"])
```

- `kit.ask(question, kind="text", choices=None, secret=False, timeout_minutes=30)`. `text` возвращает строку без пробелов по краям, `confirm` возвращает `True` или `False`, `choice` возвращает один из `choices`. `secret` бывает только у `text`.
- Kit пишет событие `ask` с уникальным `id` (буквы, цифры, `-`, `_`) и сроком `deadline` (ISO 8601, UTC) и раз в 0,2 секунды смотрит, не появился ли файл `<DAWG_SCRIPT_ANSWERS_DIR>/<id>.json`. Без этой переменной kit берёт каталог `answers` рядом с файлом событий.
- Файл ответа пишет приложение атомарно (временный файл и переименование), права 0600: `{"id": "...", "answer": ..., "secret": true|false, "ts": "..."}`. `answer` для `confirm` это `true`/`false`, для остальных строка. Ответ, который не подходит к вопросу, kit удаляет, пишет `log` уровня `warn` и ждёт дальше.
- Секретный ответ kit удаляет сразу после `ask_closed` (до него файл ответа держит вопрос закрытым для приложения) и маскирует дальше, как секреты (значения короче 3 символов не маскируются). В событиях, логах и истории его нет. Если скрипт завершился, не прочитав секретный ответ, файл удаляет приложение.
- Получив ответ, kit пишет `ask_closed` с `outcome = "answered"`, у несекретного вопроса ещё `answer`. Нет ответа до срока: `ask_closed` с `outcome = "timeout"` и исключение `kit.AskTimeout` с текстом «не дождались ответа на вопрос …». Не пойманное, оно завершает скрипт с ошибкой.
- Отмена во время ожидания работает как обычно (раздел 7): файл остановки будит ожидание.
- Ожидание ответа не продлевает `timeout_minutes` скрипта. Браузер DAWG, открытый на время вопроса, продолжает тратить минуты.
- Вопрос ждёт ответа, пока запуск идёт, нет `ask_closed`, нет файла ответа и срок не вышел. Приложение показывает его на экране запуска, отмечает запуск «ждёт ответа» на главной и в списке запусков, присылает уведомление браузера, если пользователь его разрешил. Ответить можно и из терминала: `dawg-replay answer <run_id> <ответ>` (для `confirm` `yes` или `no`, для `choice` номер или текст варианта, `-` читает ответ без отображения), а `dawg-replay run --follow` спрашивает сам.
- Автономный режим: вопрос печатается в stderr, ответ читается из терминала через `input`, секрет через `getpass`. Срок не действует. Закрытый ввод даёт `AskTimeout`.
- Скрипт с `kit.ask` указывает `contract = "1.2"`: приложение старше 1.1.0 показывает `ask` сырой строкой и не даёт ответить.
