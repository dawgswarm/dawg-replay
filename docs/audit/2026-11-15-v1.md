## Секреты

| Проверка | Статус | Доказательство |
|---|---|---|
| Ключ DAWG и секреты не попадают в события: kit маскирует их в любом поле | выполнено | `dawg-replay-kit/tests/test_events.py::test_secrets_masked_everywhere`, `test_insurance.py::test_normal_exit_closes` |
| `params.json` в каталоге запуска и параметры в БД без секретов; файл с секретами во временном каталоге 0700, удаляется после процесса | выполнено | `test_launch.py` (проверка `params.json`), `test_runner.py` |
| Секреты задаются только через хранилище паролей; `--set` и файл параметров их не принимают | выполнено | `launch.merge_values`, `dawg-replay-kit/tests/test_parameters.py::test_params_file_rejects_secrets` |
| Хвост stderr на экране, на главной, в диагнозе и в `stderr.log` маскируется | выполнено | `test_diagnosis.py::test_kit_not_found_on_run_screen` |
| `dawg-replay logs` маскирует ключ и секреты | выполнено после исправления | `test_diagnosis.py::test_cli_logs_mask_key_and_saved_secrets` |
| Ошибки проверки параметров не повторяют значение секрета | выполнено | `manifest.check_value`: для `secret` только тип значения |
| Ключ на странице настроек только подсказкой (последние 4 символа) | выполнено | `app.settings_view`, `test_web.py::test_settings_*` |

Что не маскируется: секрет короче 4 символов (`diagnosis.mask`), и старый ключ DAWG в логах запусков, сделанных до смены ключа. Оба случая оставлены как есть: короткие строки дали бы ложные замены по всему журналу, старый ключ после смены уже не работает.

## Что осталось

- Критерий 1: ручной прогон по README на чистой машине.
- Критерий 3 живым ключом: отмена, таймаут, kill -9 и закрытие UI с проверкой `list_sessions`. Минуты платные, поэтому в аудите не запускалось; тесты на фейке повторяют те же пути.
- Критерий 7: живой запуск интерфейса и скрипта на Windows и Linux.
- Версия kit: исправление проверки манифеста меняет `dawg-replay-kit`, номер версии поднимается при выпуске.
