# Независимая приёмка M3, 15.11.2026

Прогон по `docs/acceptance/m3.md` как пользователь: интерфейс и терминал, без чтения кода приложения. Сценарий с агентом не проводился, его проверяет пользователь.

## Окружение

- macOS, `main` на c35bf9c (с dr-66 и dr-68), Python 3.14 у скриптов.
- Приложение поставлено из рабочей копии: `uv tool install --from ./packages/dawg-replay --with ./packages/dawg-replay-kit dawg-replay` во временные `UV_TOOL_DIR` и `UV_TOOL_BIN_DIR`; `dawg-replay --version`: 1.1.0, контракт 1.2.
- Отдельный `DAWG_REPLAY_HOME`, временное хранилище паролей (файл 0600 вне репозитория, системное не трогалось), `dev_kit_source` на рабочую копию.
- Планировщик подменён: `DAWG_REPLAY_CRONTAB` указывает на скрипт, который хранит таблицу в файле. Задание «по расписанию» запускалось строкой из этой таблицы через `env -i`, как это сделал бы cron.
- Интерфейс открывался в Chromium без окна (Playwright), снимки оттуда.
- Ключ DAWG разработки. До прогона на ключе 0 сессий, после 0. За прогон 15 браузеров открыто и 15 закрыто, предупреждений «возможно, остался браузер» нет, ≈ 2,1 мин по оценке приложения.

Кроме демо `examples/the-internet-actions` (секретная таблица, вопросы, сохранённый вход) использовался свой скрипт `orders-check` без браузера: обычная таблица с колонками `order`, `city`, дата `since` с `min`/`max`, вопрос с выбором и подтверждение с ожиданием 1 минута, `kit.item` по строкам.

## Находки

Порядок: сначала то, что ломает сценарий пользователя.

### 1. Регулярный запуск с секретной таблицей молча не работает

Пресет у скрипта с `table` и `secret = true` сохраняется без таблицы, расписание по нему добавляется, а каждый плановый запуск падает до создания запуска. В интерфейсе этого не видно: ни запуска в истории, ни «Требует внимания», у расписания по-прежнему «следующий завтра 09:00» ([снимок](i11-failed-schedule-silent.png)). Причина есть только в `schedules/<id>.log`.

1. Демо `the-internet-actions`: загрузить `accounts.csv`, сохранить пресет «демо». Сообщение «Пресет «демо» сохранён», о том, что таблица в него не вошла, ничего не сказано ([снимок](i10-secret-preset.png)).
2. «Регулярный запуск», пресет «демо», «Добавить расписание»: добавлено.
3. Выполнить строку задания из crontab. Код 1, в логе расписания «`accounts`: обязательный параметр «Аккаунты» не задан». Главная и страница скрипта без изменений.

Ожидалось: предупреждение при сохранении пресета и отказ или предупреждение при добавлении расписания; упавший плановый запуск виден в истории или на главной.

### 2. Кнопка «Остановить» на экране идущего запуска без текста

В шапке экрана запуска кнопка выглядит красным прямоугольником без надписи: у `button.secondary.danger` цвет текста равен цвету фона (`rgb(179, 38, 30)` и `rgb(179, 38, 30)`). На главной та же кнопка (`secondary danger small`) с белым текстом. Снимки: [шапка](i04-ask-code-stop-button.png), [кнопка](i12-stop-button.png).

1. Запустить любой скрипт из интерфейса, открыть экран запуска, пока он идёт.

### 3. Отмена во время вопроса: драйвер Playwright закрыт раньше уборки

После dr-68. Отмена, пока скрипт ждёт ответа и браузер открыт: в журнале «вход не сохранён (TargetClosedError): браузер уже закрыт или недоступен», в stderr `Future exception was never retrieved … Connection closed while reading from the driver` ([снимок](i09-cancel-at-code.png), запуск 20261115-115226-4fde5b). Браузеры при этом освобождены, лишний вход не сохранён. Отмена после входа без вопроса (запуск 20261115-115353-15142f) прошла чисто, вход сохранён.

1. Стереть сохранённые входы, запустить демо из интерфейса, «Да» на первый вопрос.
2. Дождаться строки, где спрашивается код (у демо это первый настоящий вход), и, не отвечая, нажать «Остановить».

### 4. Таймаут вопроса показан как «скрипт ничего не сообщил» и трейсбек

На экране упавшего по таймауту запуска: «Скрипт ничего не сообщил. Последние строки вывода ошибок» и трейсбек целиком, хотя в журнале 5 записей и последняя из них «не дождались ответа на вопрос …». На главной в «Требует внимания» текст «dawg_replay_kit.ask.AskTimeout: не дождались …» с именем класса. Предлагается «Починить с агентом», хотя скрипт исправен, просто никто не ответил ([снимок](i03-ask-timeout.png), запуск 20261115-114031-ee23b5).

1. Скрипт с `kit.ask(..., timeout_minutes=1)`, запустить, не отвечать минуту.

### 5. Трейсбек шире карточки: страница прокручивается вбок

Тот же экран, что в п. 4: длинные строки путей в блоке stderr растягивают страницу, `scrollWidth` 1780 при ширине окна 1280. На снимке пути сокращены, поэтому прокрутки на нём нет.

### 6. Счётчик «Журнал N сообщений» не растёт на открытом экране

Экран запуска, открытый до появления записей, показывает «0 сообщений» до конца запуска, хотя записи приходят. После перезагрузки число верное («5 сообщений»). Видно на снимках [таймаута](i03-ask-timeout.png) и [отмены](i09-cancel-at-code.png).

### 7. Разное число строк у отменённого запуска в списке и на экране

Запуск 20261115-115226-4fde5b (отмена на строке 4 из 5): на экране «2 из 5 сделаны» и «до 3 строк скрипт не дошёл», в «Последних запусках» на главной «2 из 2».

### 8. Демо изменено без подъёма версии

dr-68 поменял `examples/the-internet-actions/script.py` (добавлен `b.save_login()`), `version = 1` осталась. У того, кто уже добавлял демо, `dawg-replay add examples/the-internet-actions/script.py` отвечает «версия 1 … уже зарегистрирована с другим содержимым. Поднимите `version`». В прогоне взята копия с `version = 2`.

### 9. Мелочи

- Консоль браузера при каждой загрузке таблицы в форму: `The selector "find button[type=submit]" on hx-disabled-elt returned no matches!`.
- Метки строк демо «2 № 2», «3 № 3»: ключ совпадает с номером строки. В CSV приложения те же две одинаковые колонки «Строка» и «Номер в таблице».
- На экране демо две разные кнопки CSV: «Скачать report.csv» (файл скрипта, `,`) и «Скачать отчёт CSV» (приложение, `;`).
- Блок «Шаги» у завершённого запуска: последний шаг с точкой, как у идущего.
- Демо: «Пройти по 1 строкам таблицы».
- `dawg-replay logins list`: время в UTC ISO (`2026-11-15T11:43:16Z`), в интерфейсе «сегодня 18:43».

## Не проверено

- Сценарий с агентом (по решению лида проверяет пользователь).
- Windows и Linux вручную: только CI.
- «Забыть все» в интерфейсе: в прогоне был один вход; стирание всех проверено командой `dawg-replay logins forget the-internet-actions --all`.
