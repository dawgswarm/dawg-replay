# Приёмка M5, часть 1: уведомления в Telegram

План ручной проверки по спеке `docs/specs/2026-11-16-m5-telegram.md` на вашем настоящем боте. Каждый
сценарий: подготовка, шаги, что должно получиться, что отметить. Результаты пишите в таблицу в конце
(или прямо под сценарием), к расхождениям прикладывайте снимок экрана Telegram или приложения.

Почти всё проверяется демо [`examples/telegram-demo`](../../examples/telegram-demo/README.md): оно без
браузера и сайта, минуты DAWG не тратит, умеет работать заданное время, задавать вопрос и заканчиваться
любым итогом. Один сценарий (Д2) по желанию повторяется на настоящем браузере с `the-internet-task`.

## Что понадобится

- Telegram на телефоне или компьютере.
- Свой бот: в Telegram найдите @BotFather, отправьте `/newbot`, придумайте имя и username (на `bot`),
  сохраните токен из ответа. Для сценария П3 нужен второй бот (тот же путь, другое имя).
- dawg-replay 1.3.0: `dawg-replay --version`.
- Компьютер включён, вы в системе: регулярные запуски идут через системный планировщик.

## Подготовка

1. Добавьте демо:

       dawg-replay add examples/telegram-demo/script.py

   Демо не открывает браузер; если ключ DAWG не задан, предупреждение «ключ DAWG не задан» при запуске можно не замечать.
2. Чтобы не ждать 10 минут, порог «долгого» ручного запуска на время приёмки: Настройки, блок
   Telegram, «Долгим считается ручной запуск дольше, минут» = 2 (или `dawg-replay telegram set long_minutes 2`).
   В конце верните 10.
3. Пресеты для регулярных запусков (значения пресета видны в форме скрипта):

       dawg-replay preset save telegram-demo ок --set outcome=ok --set minutes=0.2
       dawg-replay preset save telegram-demo да-нет --set ask=confirm --set ask_minutes=10
       dawg-replay preset save telegram-demo код --set ask=code --set ask_minutes=10

4. Как поставить регулярный запуск на ближайшие минуты. На macOS и Linux каждые 5 минут:

       dawg-replay schedule add telegram-demo --preset да-нет --cron "*/5 * * * *"

   На Windows раз в день на время через 3 минуты от текущего (например, сейчас 14:07):

       dawg-replay schedule add telegram-demo --preset да-нет --daily 14:10

   После сценария снимайте расписание: `dawg-replay schedule list`, затем `dawg-replay schedule remove <id>`.

Обозначения ниже: «экран Telegram» это блок Telegram в Настройках приложения, «журнал запуска» это
журнал на экране запуска (или `dawg-replay logs <запуск>`).

## П. Подключение

### П1. Подключение из Настроек

1. `dawg-replay ui`, Настройки, блок Telegram. Блок предлагает создать бота у @BotFather и вставить токен.
2. Вставьте неверный токен (например, сотрите последний символ), «Проверить и привязать чат».
3. Вставьте верный токен.
4. Нажмите «Открыть в Telegram», в боте нажмите «Start».

Ожидается:
- на шаге 2 ошибка «токен бота не подходит: проверьте его у @BotFather», токен не сохранён;
- на шаге 3 «Бот @<ваш бот> найден», кнопка «Открыть в Telegram», команда `/start <код>` и «Жду до ЧЧ:ММ» (5 минут);
- после «Start» блок сам, без перезагрузки, показывает «Подключено: бот пишет в чат «<ваше имя>»…»;
- бот ответил «Подключено к dawg-replay…»;
- после перезагрузки страницы: «Подключено: бот @…, чат «…»», кнопки «Отправить проверочное» и «Отключить», ниже галочки «О чём писать».

Отметить: [ ] неверный токен не принят, [ ] ссылка открывает бота, [ ] подключение без перезагрузки, [ ] ответ бота.

### П2. Чужие и неверные /start не привязывают

1. Отключите Telegram («Отключить»), вставьте токен снова, ссылку пока не открывайте.
2. В боте вручную отправьте `/start` без кода, затем `/start 123`.
3. Попросите кого-то другого открыть вашу ссылку (или откройте её с другого аккаунта Telegram) и нажать «Start».
   Если второго аккаунта нет, пропустите и отметьте.
4. Отправьте боту правильную команду `/start <код>` руками (скопируйте из блока).

Ожидается: шаги 2 и 3 ничего не привязывают, блок продолжает ждать; на шаге 4 подключено. Если другой
человек успел раньше вас, подключится его чат: это ожидаемо (код одноразовый и виден только на вашем
экране), но отметьте, если так вышло.

Отметить: [ ] `/start` без кода и с чужим кодом не привязали, [ ] правильная команда руками привязала.

### П3. Повторная привязка и другой бот

1. Подключено (П1). Выполните `dawg-replay telegram connect --same-token --wait 30` и ничего не отправляйте 30 секунд.
2. `dawg-replay telegram test`.
3. `dawg-replay telegram connect`, вставьте токен второго бота, сразу прервите Ctrl+C.
4. `dawg-replay telegram status`.
5. Снова `dawg-replay telegram connect` с токеном первого бота, откройте ссылку, «Start».

Ожидается:
- шаг 1: «сообщение /start … не пришло за 1 мин.»; шаг 2: проверочное пришло в прежний чат (чат не сбросился);
- шаг 3: токен второго бота сохранён, прежний чат сброшен сразу; шаг 4: «бот @<второй> сохранён, чат не привязан»;
- шаг 5: подключено к первому боту.

Отметить: [ ] неудачная повторная привязка тем же ботом не отключила уведомления, [ ] другой бот сбрасывает чат сразу.

### П4. Проверочное и последняя ошибка

1. «Отправить проверочное» в Настройках и `dawg-replay telegram test`.
2. В Telegram заблокируйте бота (профиль бота, «Остановить и заблокировать»), снова «Отправить проверочное».
3. Разблокируйте бота (нажмите «Перезапустить» или Start), «Отправить проверочное».

Ожидается: шаг 1 оба сообщения «Проверка связи…» пришли; шаг 2 ошибка «бот не может написать в чат…» и
под блоком «Последняя ошибка отправки, сегодня ЧЧ:ММ: …»; шаг 3 сообщение пришло, строка ошибки пропала.

Отметить: [ ] проверочное из UI и CLI, [ ] понятная ошибка при блокировке, [ ] ошибка уходит после удачной отправки.

### П5. Токен нигде не виден

1. `dawg-replay config show`: в выводе каталог данных и `telegram_chat_id`, `telegram_bot`; токена нет.
2. Поиск части токена (после двоеточия, первые 10 символов) по каталогу данных:

       grep -r "<часть токена>" "<каталог данных>"          # macOS, Linux
       findstr /s /m "<часть токена>" "<каталог данных>\*"   # Windows

3. Откройте исходный код страницы Настроек (Ctrl+U) и поищите ту же часть.

Ожидается: ничего не найдено. Токен только в системном хранилище паролей (на macOS «Связка ключей», запись `dawg-replay`, `telegram-bot-token`).

Отметить: [ ] токена нет в файлах, [ ] нет на странице.

## Р. Регулярные запуски при закрытом UI

Перед каждым сценарием этого раздела закройте `dawg-replay ui` (Ctrl+C в терминале) и закройте вкладку.

### Р1. Успешный регулярный запуск

Расписание с пресетом `ок` (Подготовка, п. 4). Дождитесь запуска.

Ожидается сообщение:
- «Готово: Демо уведомлений в Telegram, пресет «ок»»;
- «собрано 50», «Собрано записей: 50», «Как устроены уведомления: https://core.telegram.org/bots»;
- «Шёл …, начат сегодня ЧЧ:ММ», последняя строка «В приложении: Запуски, …, сегодня ЧЧ:ММ»;
- ссылки на экран запуска и токена входа нет.

Отметить: [ ] сообщение пришло без открытого UI, [ ] текст понятный, без технических слов.

### Р2. Вопрос-подтверждение из регулярного запуска

Расписание с пресетом `да-нет`. Дождитесь сообщения с вопросом.

1. Сообщение: название скрипта, «Вопрос: Демо: продолжить запуск?», «Нажмите кнопку с ответом», «Ответить до ЧЧ:ММ», кнопки «Да» и «Нет».
2. Нажмите «Да».
3. Нажмите «Да» ещё раз (если кнопки остались) или «Нет».
4. Откройте `dawg-replay ui`, экран этого запуска.

Ожидается: после шага 2 сообщение с вопросом исправлено на «Ответ принят»; запуск закончился, пришло «Готово: …, пресет «да-нет»» с «подтверждено»;
на шаге 3 «Уже отвечено» или «Вопрос закрыт», запуск не меняется; в журнале запуска ответ «да».

Отметить: [ ] вопрос пришёл при закрытом UI, [ ] кнопка сработала, [ ] повторное нажатие не меняет ответ.

### Р3. Секретный код из регулярного запуска

Расписание с пресетом `код`. Дождитесь вопроса.

1. Сообщение «Вопрос: Демо: введите любой код…», «Чтобы ответить, ответьте на это сообщение (Ответить)», «Ответ секретный: бот сразу удалит ваше сообщение с ним».
2. Ответьте на это сообщение (Ответить) кодом `48151623`.
3. После итога: экран запуска и `dawg-replay logs <запуск> --events`, затем поиск кода по каталогу данных (как в П5).

Ожидается: ваше сообщение с кодом исчезло из чата через секунду-две; вопрос исправлен на «Ответ принят» без значения;
итог «Готово: …, пресет «код»», «код получен (8 симв.)»; кода нет ни на экране, ни в журнале, ни в файлах. Если удалить сообщение
не удалось, бот пишет «Не удалось удалить сообщение с кодом, удалите его сами».

Отметить: [ ] сообщение с кодом удалено, [ ] кода нигде нет, [ ] запуск получил код.

### Р4. Вопрос без ответа

`dawg-replay run telegram-demo --set ask=confirm --set ask_minutes=1` (в фоне, UI закрыт). Не отвечайте.

Ожидается: через минуту вопрос исправлен на «Срок ответа вышел» (или «Вопрос закрыт: запуск завершился»);
пришло «Упал: Демо уведомлений в Telegram» с причиной «не дождались ответа за 1 мин.». Нажатие на старую кнопку даёт «Вопрос закрыт».

Отметить: [ ] вопрос закрылся, [ ] пришло сообщение о падении.

## В. Вопросы: варианты ответа

### В1. Выбор, текст и простое сообщение

1. `dawg-replay run telegram-demo --set ask=choice`: кнопки «Москва», «Казань», «Петербург», нажмите «Казань».
2. `dawg-replay run telegram-demo --set ask=text`: напишите боту просто «привет» (не через «Ответить»).

Ожидается: 1) итог с «выбран город Казань»; 2) ответ принят, хотя вы не нажимали «Ответить» (вопрос был один), итог с «ответ «привет»».

Отметить: [ ] выбор кнопкой, [ ] простое сообщение при одном вопросе.

### В2. Несколько вопросов сразу

1. Запустите два фоновых запуска подряд: `dawg-replay run telegram-demo --set ask=text` два раза.
2. Напишите боту просто «раз».
3. Ответьте (Ответить) на первый вопрос «раз», на второй «два».

Ожидается: на шаге 2 бот отвечает «Ответа ждут несколько вопросов: ответьте на сообщение с нужным вопросом (Ответить)»
и ничего не засчитывает; после шага 3 первый запуск закончился с «ответ «раз»», второй с «ответ «два»», ответы не перепутаны.

Отметить: [ ] простое сообщение не ушло наугад, [ ] каждый ответ ушёл своему запуску.

### В3. Ответ сразу из двух мест

`dawg-replay ui`, запуск с `ask=confirm`. Ответьте «Да» на экране запуска, затем нажмите «Нет» в Telegram.

Ожидается: засчитан первый ответ «Да»; в Telegram «Уже отвечено» или «Вопрос закрыт», сообщение с вопросом исправлено.

Отметить: [ ] засчитан первый ответ.

## Ч. Ручные запуски и итоги

### Ч1. Порог долгого ручного запуска

Настройки: «Ручной запуск закончился» = «если дольше N минут», порог 2 (Подготовка, п. 2).

1. В UI на форме скрипта поле «Сообщить в Telegram, когда закончится»: «по настройкам: если дольше 2 минут». Запустите с `minutes=0.5`.
2. Запустите с `minutes=3`.
3. В CLI: `dawg-replay run telegram-demo --set minutes=0.5 --follow` и `dawg-replay run telegram-demo --set minutes=3`.

Ожидается: запуски по 0,5 минуты сообщения не дают, по 3 минуты дают «Готово: …», «Шёл 3 мин…».

Отметить: [ ] короткий молчит, [ ] долгий пишет, [ ] из UI и из CLI одинаково.

### Ч2. Выбор у запуска

1. В форме «Сообщить…» = «всегда», `minutes=0`: сообщение приходит.
2. `dawg-replay run telegram-demo --set minutes=3 --no-notify`: сообщения нет.
3. `dawg-replay run telegram-demo --notify --follow`: сообщение есть.
4. `dawg-replay run telegram-demo --set outcome=failed --no-notify`: сообщение о падении всё равно приходит (выбор касается только успешного итога).

Отметить: [ ] «всегда», [ ] `--no-notify`, [ ] `--notify`, [ ] падение приходит и при `--no-notify`.

### Ч3. Падения

1. `dawg-replay run telegram-demo --set outcome=failed`.
2. `dawg-replay run telegram-demo --set outcome=crash`.
3. Необязательно, «не начался»: `dawg-replay config set max_parallel_runs 1`, `dawg-replay config set wait_slot_minutes 1`,
   запустите `dawg-replay run telegram-demo --set minutes=3`, сразу поставьте регулярный запуск на ближайшую минуту. Плановый
   не дождётся места. Верните `max_parallel_runs` 3 и `wait_slot_minutes` 30.

Ожидается: 1) «Упал: …», «сайт демо не ответил»; 2) «Упал: …» с той же причиной, что на экране запуска («Скрипт завершился с ошибкой…»);
3) «Упал: …, пресет «…»», «Не начался: все места для одновременных запусков были заняты, а время ожидания вышло».

Отметить: [ ] падение с объяснением, [ ] падение без итога, [ ] пропущенный плановый (если проверяли).

### Ч4. Частичный итог

`dawg-replay run telegram-demo --set outcome=partial --notify`.

Ожидается: «Готово частично: …», «3 из 5 строк, 2 упали», строка про строки (сделано 3, упало 2), «Собрано записей: 3».

Отметить: [ ] видно, что частично и сколько упало.

### Ч5. Тихая поломка

`dawg-replay run telegram-demo --set count=0 --notify`.

Ожидается: «Готово: …», «собрано 0» и строка «Похоже, сайт поменялся. Запуск завершился без ошибки, но скрипт сообщил, что собрал 0 записей.»
На главной этот запуск в «Требует внимания» с тем же текстом. Затем снимите галочку «Похоже, сайт поменялся» в Настройках и повторите: итог приходит без этой строки.

Отметить: [ ] строка о поломке в сообщении, [ ] галочка её убирает.

### Ч6. Главный файл документом

Включите «Приложить главный файл итога», `dawg-replay run telegram-demo --set count=200 --notify`.

Ожидается: в сообщение об итоге приложен `result.csv` (200 строк, открывается). Выключите галочку обратно.

Отметить: [ ] файл пришёл и открывается.

### Ч7. Отмена молчит

1. `dawg-replay ui`, запуск с `minutes=3` и «Сообщить… = всегда», через полминуты «Отменить» на экране запуска.
2. Тот же запуск снова, через полминуты остановите `dawg-replay ui` Ctrl+C.
3. `dawg-replay run telegram-demo --set minutes=3 --notify --follow`, через полминуты Ctrl+C.

Ожидается: ни одного сообщения в Telegram (запуски со статусом «отменён»).

Отметить: [ ] отмена из UI, [ ] остановка сервера UI, [ ] Ctrl+C в терминале.

## О. Переопределения у скрипта и расписания

### О1. Скрипт

1. Страница скрипта `telegram-demo`, блок «Уведомления в Telegram»: «как в общих настройках». Поставьте «Ручной запуск закончился» = «никогда», сохраните.
2. `dawg-replay run telegram-demo --set minutes=3`: сообщения нет. Запуск с `--notify`: есть (выбор у запуска главнее).
3. Если добавлен `the-internet-task` (Д2) или другой скрипт: его долгий ручной запуск по-прежнему пишет (общие настройки не изменились).
4. `dawg-replay telegram set --script telegram-demo`: видно своё значение у `done_manual` («своё»), у остальных «наследуется».
5. `dawg-replay telegram set done_manual inherit --script telegram-demo`: блок на странице снова «как в общих настройках».

Отметить: [ ] своё правило у скрипта, [ ] запуск главнее скрипта, [ ] другие скрипты не задеты, [ ] inherit возвращает общее.

### О2. Расписание

1. Расписание с пресетом `ок`. В блоке «Регулярный запуск» на странице скрипта у этого расписания «Уведомления в Telegram, как у скрипта». Поставьте «Запуск по расписанию закончился» = «не писать».
2. У скрипта в это же время «Запуск по расписанию закончился» = «писать» (своё значение).
3. Дождитесь запуска: сообщения нет (расписание главнее скрипта). Падение того же расписания (пресет с `outcome=failed`) при этом приходит, если `failed` не выключен.
4. У расписания нет пункта «Ручной запуск закончился».
5. Верните «как у скрипта» и у расписания, и у скрипта.

Отметить: [ ] расписание главнее скрипта, [ ] других событий это не задело, [ ] нет пункта про ручной запуск.

## Н. Недоступный Telegram

### Н1. Неверный адрес Bot API

1. `dawg-replay config set telegram_api_url https://127.0.0.1:9`.
2. `dawg-replay run telegram-demo --notify --follow` и запуск с `ask=confirm` из UI (ответьте на экране запуска).
3. Регулярный запуск с пресетом `ок` при закрытом UI.
4. `dawg-replay config set telegram_api_url ""`, затем `dawg-replay ui` (или любой следующий запуск).

Ожидается:
- шаги 2 и 3 закончились обычным итогом «готово», без лишнего ожидания (на сообщение уходят секунды, запуск их не ждёт);
- в журнале запуска строка вида «Сообщение об итоге в Telegram не отправлено: Telegram недоступен…», в Настройках «Последняя ошибка отправки»;
- вопрос на шаге 2 отвечается из UI как обычно;
- после шага 4 неотправленные итоги не старше суток приходят (по одному разу, без повторов).

Отметить: [ ] запуск не сломался и не задержался, [ ] ошибка в журнале и в Настройках, [ ] досылка после восстановления без дублей.

## Д. Отключение и настоящий браузер

### Д1. Отключение

1. Настройки, «Отключить», подтвердить.
2. `dawg-replay telegram status`; страница скрипта, блок «Уведомления в Telegram».
3. `dawg-replay run telegram-demo --set outcome=failed` и запуск с `ask=confirm` (ответьте в UI или `dawg-replay answer`).

Ожидается: «Telegram отключён, токен бота стёрт из хранилища паролей»; status «Telegram не подключён»; на странице скрипта
«Подключить в Настройках»; запуски идут как обычно, в Telegram ничего, новых ошибок в журнале нет. В хранилище паролей записи `telegram-bot-token` нет.

Отметить: [ ] токен стёрт, [ ] запуски без сообщений и без ошибок.

### Д2. Необязательно: настоящий браузер

Подключите Telegram снова, `dawg-replay add examples/the-internet-task/script.py`,
`dawg-replay run the-internet-task --set mode=act --notify` (нужен ключ DAWG).

Ожидается: вопрос «Нажать Start на учебной странице?» в Telegram, после «Да» итог «Готово: Учебный сайт…» со строкой итога и ссылкой «Учебная страница».

Отметить: [ ] вопрос и итог настоящего скрипта.

## После приёмки

- Порог долгого запуска обратно 10, `max_parallel_runs` 3, `wait_slot_minutes` 30, `telegram_api_url` пусто.
- Снимите расписания демо: `dawg-replay schedule list`, `dawg-replay schedule remove <id>`.
- Демо можно удалить: `dawg-replay remove telegram-demo`.
