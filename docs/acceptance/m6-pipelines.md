# Приёмка M6: связи между скриптами

План ручной проверки по спеке `docs/specs/2026-11-16-m6-pipelines.md`. Каждый сценарий: подготовка, шаги, что
должно получиться, что отметить. Результаты пишите в таблицу в конце (или прямо под сценарием), к расхождениям
прикладывайте снимок экрана приложения.

Всё проверяется на демо [`examples/pipeline-demo`](../../examples/pipeline-demo/README.md): шесть скриптов без
браузера и сайта, минуты DAWG не тратят, ключ DAWG не нужен. Источники умеют работать заданное время, падать,
заканчиваться частично и «ломать» файл (колонка `cost` вместо `price`).

## Что понадобится

- dawg-replay 1.4.0: `dawg-replay --version`, в `contract_versions` есть `1.4`.
- Компьютер включён, вы в системе: срок ожидания «после всех» и регулярные запуски срабатывают без открытого UI
  через отдельный процесс ожидания и планировщик системы.

## Подготовка

1. Добавьте демо (macOS и Linux; на Windows по одному файлу):

       for f in examples/pipeline-demo/demo-*.py; do dawg-replay add "$f"; done

2. Если вы уже проверяли связи, удалите старые: `dawg-replay link list`, затем `dawg-replay link remove <id>`.

Обозначения: «журнал запуска» это журнал на экране запуска (или `dawg-replay logs <запуск>`), «журнал связи»
это последние решения в `dawg-replay link show <источник> <получатель>` и на панели связи на экране «Связи».

## Ц. Цепочка WB + Ozon → обновление → отчёт

### Ц1. Сборка командами

    dawg-replay link add demo-wb-prices demo-update-prices --file prices.csv=wb
    dawg-replay link add demo-ozon-prices demo-update-prices --file prices.csv=ozon
    dawg-replay link add demo-update-prices demo-report --file @main=updated
    dawg-replay link mode demo-update-prices all --wait 5m --on-timeout skip
    dawg-replay link list
    dawg-replay link check

Ожидается:
- каждое `link add` отвечает «связь добавлена: <id>  <источник> → <получатель>  после успешного; prices.csv → wb»
  и подсказкой `dawg-replay link check`;
- `link mode`: «demo-update-prices: после всех, ждать отстающего 5 мин, по сроку пропустить»;
- `link check`: «связей: 3, ошибок нет».

Отметить: [ ] связи добавлены, [ ] режим получателя, [ ] проверка без ошибок.

### Ц2. Экран «Связи» и блок скрипта

1. `dawg-replay ui`, экран «Связи».
2. Откройте страницу `demo-update-prices`, блок связей, ссылку «открыть на карте».

Ожидается: на карте четыре скрипта, сплошные стрелки WB → обновление, Ozon → обновление, обновление → отчёт,
подписи `prices.csv → wb`, `prices.csv → ozon`, `главный файл → updated`; у узла обновления подпись «после всех».
Ping и pong не показаны, пока нет их связей (или видны с переключателем «показать все скрипты»). Блок на странице
скрипта: «откуда берёт данные: Цены WB, Цены Ozon → этот скрипт → Отчёт».

Отметить: [ ] карта, [ ] подписи стрелок и режим, [ ] блок на странице скрипта.

### Ц3. Цепочка идёт сама

    dawg-replay run demo-wb-prices --follow
    dawg-replay run demo-ozon-prices --follow

Подождите несколько секунд, затем `dawg-replay runs demo-update-prices` и `dawg-replay runs demo-report`.

Ожидается:
- после WB обновление ещё не запущено (ждёт Ozon); в журнале связи WB → обновление «ждёт остальных источников»;
- после Ozon обновление запустилось один раз, затем сам запустился отчёт;
- на экране запуска обновления строка «Запущен после: Цены Ozon» и ссылки на оба запуска-источника, файлы
  `wb` и `ozon` из них; у запуска WB «Передал в: Обновить мои цены»;
- в `updated.csv` у каждого `sku` новая цена равна меньшей из двух минус 1; отчёт: «товаров 5, средняя цена …».

Отметить: [ ] получатель ждал второго источника, [ ] один запуск обновления, [ ] отчёт после обновления,
[ ] «Запущен после» и «Передал в», [ ] данные в файлах.

### Ц4. Telegram (если подключён)

После Ц3 в Telegram пришли сообщения об итоге обновления и отчёта как о плановых, со строкой «после: <источник>».
Ручные запуски WB и Ozon пишут по правилу ручных запусков.

Отметить: [ ] сообщения о запусках по связи со строкой «после: …».

## О. «После всех» со сроком

### О1. Срок вышел: пропуск

1. `dawg-replay run demo-wb-prices --follow`, Ozon не запускайте.
2. Закройте UI. Подождите 5-6 минут.
3. `dawg-replay runs demo-update-prices`, главная в UI.

Ожидается: через 5 минут (опоздание не больше пары минут) у обновления запись «пропущен» с причиной о сроке
ожидания Цены Ozon; она в «Требует внимания» на главной; в Telegram сообщение о падении. Отчёт не запускался.

Отметить: [ ] пропуск по сроку без открытого UI, [ ] причина понятна, [ ] отчёт не запущен.

### О2. Срок вышел: запустить с тем, что есть

    dawg-replay link mode demo-update-prices all --wait 5m --on-timeout run

Повторите О1. Ожидается: через 5 минут обновление запустилось с файлом WB из нового запуска и файлом Ozon из
последнего успешного запуска Ozon (из Ц3); в журнале запуска видно, из каких запусков взяты файлы.

Отметить: [ ] запуск по сроку, [ ] Ozon из прошлого успешного запуска.

### О3. Неподходящий исход, повтор в пределах срока

1. Верните `--on-timeout skip`.
2. `dawg-replay run demo-wb-prices --set outcome=failed --follow`.
3. `dawg-replay run demo-ozon-prices --follow`.
4. В пределах 5 минут `dawg-replay run demo-wb-prices --follow`.

Ожидается: после шага 2 в журнале связи WB → обновление «не запущен: Цены WB упал» (в истории обновления записи
нет); после шага 3 обновление ждёт; после шага 4 обновление запустилось один раз с обоими файлами.

Отметить: [ ] упавший источник не запускает и не шумит в истории, [ ] повторный успешный засчитан.

### О4. Компьютер был выключен (по желанию)

1. Срок 5 минут, `--on-timeout run`, запустите только WB.
2. Сразу усыпите компьютер минут на 10, затем разбудите и выполните любую команду, например `dawg-replay runs`.

Ожидается: обновление запустилось после пробуждения, в его журнале строка «срок ожидания вышел в ЧЧ:ММ, запущен
позже: компьютер был выключен».

Отметить: [ ] запуск после пробуждения со строкой о позднем сроке.

### О5. «После любого»

    dawg-replay link mode demo-update-prices any

Запустите WB, затем Ozon. Ожидается: обновление запустилось дважды, каждый раз с самыми свежими файлами обоих
источников на тот момент; отчёт тоже дважды. Верните `all`.

Отметить: [ ] запуск после каждого источника.

## К. Несовпадение колонок

### К1. При сохранении связи (выходы объявлены)

    dawg-replay link add demo-wb-prices demo-report --file prices.csv=updated --after never

Ожидается: связь не сохранена: в параметр `updated` уже передаёт файл связь demo-update-prices → demo-report
(один параметр получает файл одной связи). Снимите связь обновление → отчёт (`dawg-replay link remove
demo-update-prices demo-report`) и повторите: связь сохранена с предупреждением «в `prices.csv` нет колонки
`new_price`, нужны параметру `updated`»; то же в `dawg-replay link check` (код выхода 0) и красной стрелкой на
карте. Удалите эту связь и верните обновление → отчёт.

Отметить: [ ] предупреждение при сохранении, [ ] в `link check`, [ ] на карте.

### К2. Перед стартом получателя

1. `dawg-replay run demo-wb-prices --follow`.
2. `dawg-replay run demo-ozon-prices --set broken=true --follow`.

Ожидается: обновление не начато (`not_started`), причина «Демо: цены Ozon, prices.csv: в шапке нет колонок:
«price», нужна параметру `ozon`»; запись в истории и «Требует внимания», сообщение о падении в Telegram; отчёт не
запускался. То же без связей ссылкой:

    dawg-replay run demo-update-prices --set wb=last:demo-wb-prices:prices.csv --set ozon=last:demo-ozon-prices:prices.csv --follow

даёт ошибку с тем же текстом до старта.

Отметить: [ ] получатель не стартовал с понятной причиной, [ ] то же для ссылки.

## Р. Круг с пределом

1. `dawg-replay link add demo-ping demo-pong --file @main=ball`
2. `dawg-replay link add demo-pong demo-ping --file @main=ball`
3. `dawg-replay link add demo-pong demo-ping --file @main=ball --limit-per-day 3`
4. `dawg-replay run demo-ping --follow`, подождите полминуты.
5. `dawg-replay runs demo-ping`, `dawg-replay runs demo-pong`, `dawg-replay link show demo-pong demo-ping`.

Ожидается:
- шаг 2: «связь не сохранена: круг без предела: demo-pong → demo-ping → demo-pong. Задайте на одной из связей
  круга предел запусков в сутки (--limit-per-day N)»;
- шаг 3: связь добавлена «[не больше 3 в сутки]»; `link check` без ошибок;
- мяч ходит туда и обратно: итоги «удар 1: пинг», «удар 2: понг», …; по связи понг → пинг ровно 3 запуска за
  сутки, затем в журнале связи «не запущен: предел 3 в сутки исчерпан», лишних записей в истории нет;
- на карте круг из двух стрелок, у одной подпись предела.

Отметить: [ ] круг без предела не сохраняется, [ ] предел соблюдён, [ ] причина остановки видна.

## У. Ручная передача и правка схемы в UI

### У1. «Передать в другой скрипт»

1. Экран завершённого запуска `demo-wb-prices`, кнопка «Передать в другой скрипт».
2. Выберите `demo-update-prices`: `prices.csv` предложен в параметр `wb` (совпадают колонки).
3. Откроется форма запуска с подставленным значением «из результата Цены WB, запуск от …»; запустите.
4. Рядом с подстановкой предложение «запускать так всегда».

Ожидается: запуск прошёл с файлом из выбранного запуска; связь не создана, пока не нажато «запускать так
всегда»; после нажатия связь видна на карте.

Отметить: [ ] передача файлов разово, [ ] предложение создать связь.

### У2. Правка мышкой

1. На экране «Связи» включите «показать все скрипты», протяните стрелку от `demo-report` к `demo-ping`.
2. В открывшейся панели выберите «не запускать, только файл», сохраните.
3. Клик по стрелке WB → обновление: выключите связь; клик по узлу обновления: режим и срок.
4. Перетащите узлы и обновите страницу.

Ожидается: новая связь пунктирной стрелкой; выключенная видна бледной и ничего не запускает (проверьте запуском
WB: в журнале связи «связь выключена»); режим и срок меняются в панели узла; раскладка сохранилась.

Отметить: [ ] создание стрелкой, [ ] настройки связи и узла, [ ] выключенная связь, [ ] раскладка.

### У3. Ссылка в пресете и по расписанию

1. `dawg-replay preset save demo-report из-обновления --set updated=last:demo-update-prices:updated.csv`
2. `dawg-replay run demo-report --preset из-обновления --follow`.
3. На карте у отчёта пунктирная стрелка от обновления (ссылка из пресета).

Ожидается: отчёт взял последний успешный `updated.csv`; ссылка видна на карте.

Отметить: [ ] ссылка из пресета работает, [ ] видна на карте.

## Уборка

`dawg-replay remove <скрипт>` для каждого демо-скрипта: связи удаляются вместе с ними.
