# M3: действия на сайтах по таблице

Цель: кроме сбора данных, скрипты выполняют действия на сайтах: проходят по строкам таблицы, входят в кабинет, заполняют формы, проверяют результат. Клиент загружает Excel или CSV, видит, какие строки сделаны и какие упали, перезапускает только упавшие. Если сайт спрашивает код из SMS или нужно подтверждение, скрипт спрашивает человека посреди запуска.

Контракт 1.2, расширение аддитивное: скрипты с `contract = "1.1"` работают как раньше. dawg-replay-kit 1.2.0, dawg-replay 1.1.0.

## 1. Параметры `date` и `table` (dr-60)

`date`: строка `YYYY-MM-DD`, необязательные `min`, `max` в том же формате. В форме поле даты, в автономном режиме `--from 2026-11-01`.

`table`: таблица из файла CSV или XLSX.

- Поля: `columns?` (список колонок, которые обязаны быть в шапке), `max_rows?` (по умолчанию 10000), `secret?` (`true`: таблица целиком считается секретом).
- Разбор делает приложение при загрузке файла: первая строка шапка, пустые строки пропускаются, у XLSX берётся первый лист. Значения ячеек строками; дата в ячейке даёт `YYYY-MM-DD`, целое число без `.0`. Кодировка CSV: UTF-8 с BOM или без, запасной вариант cp1251; разделитель `,` или `;` определяется сам.
- Значение в JSON параметров: список объектов, ключи из шапки, плюс поле `_row` с номером строки в исходном файле (шапка это строка 1). Скрипт получает готовые строки и файл не разбирает.
- Форма: загрузка файла, после неё имя файла, число строк, колонки и первые 5 строк. Ошибки (нет колонки из `columns`, больше `max_rows`, пустая таблица) видны до запуска.
- Пресет хранит разобранную таблицу и имя файла. Таблица с `secret = true` в пресеты, историю запуска и логи не попадает, передаётся скрипту как секрет (временный каталог 0700), в UI видны только имя файла и число строк. Kit маскирует её значения в событиях так же, как секреты.
- CLI: `--param accounts=@path/to/file.xlsx`. Автономный режим скрипта: `--accounts file.csv` или `.xlsx`; для XLSX kit требует `openpyxl` в зависимостях скрипта и подсказывает это в ошибке.
- В приложение добавляется зависимость `openpyxl`.

## 2. Отчёт по строкам и перезапуск упавших (dr-63, после dr-60)

Новое событие `item`: `key` (строка или число), `status` (`ok`/`failed`/`skipped`), `msg?`, `row?` (значение `_row` строки таблицы).

```python
for row in kit.params["accounts"]:
    try:
        ...
        kit.item(row["email"], "ok", row=row["_row"])
    except Exception as e:
        kit.item(row["email"], "failed", str(e), row=row["_row"])
```

- Экран запуска: блок «Строки» со счётчиками по статусам и таблицей `key`, статус, сообщение; фильтр «только упавшие». Повторный `item` с тем же `key` заменяет прежний.
- Кнопка «Перезапустить упавшие»: новый запуск с теми же параметрами, в котором таблица отфильтрована до строк, чьи `row` получили `failed` (и тех, до которых скрипт не дошёл, если запуск оборвался). Доступна, когда у скрипта ровно один параметр `table` и события `item` содержат `row`. Для таблицы с `secret = true` таблица берётся из того же временного хранилища, пока оно живо, иначе кнопка просит загрузить файл заново.
- В списке запусков и на главной итог вида «48 из 50, 2 упали».
- Детектор тихой поломки учитывает `item` как записи.

## 3. Вопрос посреди запуска (dr-61)

```python
code = kit.ask("Код из SMS на номер ***-12", kind="text", secret=True, timeout_minutes=10)
ok = kit.ask("Отправить 12 заявок?", kind="confirm")
city = kit.ask("Какой склад?", kind="choice", choices=["Москва", "Казань"])
```

- Событие `ask`: `id`, `question`, `kind`, `choices?`, `secret`, `deadline`. Kit ждёт ответ в файле `<run_dir>/answers/<id>.json`, опрашивает его и файл остановки; приложение пишет ответ атомарно. Секретный ответ kit удаляет после чтения, в лог и события он не попадает.
- Нет ответа до срока: `kit.AskTimeout`, по умолчанию скрипт падает с понятной ошибкой «не дождались ответа на вопрос …».
- UI: на экране запуска заметный блок с вопросом и полем или кнопками; на главной и в списке запусков отметка «ждёт ответа»; уведомление браузера, если вкладка приложения открыта и пользователь разрешил уведомления.
- CLI: `dawg-replay answer <run_id> <ответ>` (для `confirm`: `yes`/`no`), `dawg-replay run --follow` печатает вопрос и принимает ответ из терминала.
- Автономный режим: вопрос в терминале через `input`, секрет через `getpass`.
- Время ожидания ответа не продлевает `timeout_minutes` скрипта; минуты DAWG при этом идут, если браузер открыт, и это видно в подсказке под вопросом.

## 4. Сохранённый вход (dr-62)

```python
with kit.browser(login=row["email"]) as b:   # или login="кабинет"
    ...
```

- Kit перед работой загружает в контекст сохранённые cookies и localStorage этого входа, при закрытии браузера сохраняет текущие. Скрипт сам проверяет, залогинен ли он, и входит заново, если нет; `b.login_restored` говорит, было ли что загружать. `b.forget_login()` стирает вход (например, если сайт его отозвал).
- Хранение: приложение передаёт `DAWG_SCRIPT_LOGINS_DIR` = `<home>/logins/<script>/`, каталог 0700, файл на вход 0600, имя файла это хеш имени входа, имя хранится внутри файла. В историю запусков, логи и экспорт не попадает. Автономный режим: `./logins/`.
- UI на странице скрипта: «Сохранённые входы», имя, когда сохранён и когда использован, кнопка «Забыть» и «Забыть все». CLI: `dawg-replay logins list <script>`, `dawg-replay logins forget <script> [<name>|--all]`.
- Удаление скрипта удаляет его входы.

## 5. Скилл (dr-64, после 1-4)

- Описание скилла: кроме сбора данных, действия на сайтах по списку: вход в свой кабинет, формы, обновления, проверки.
- Разведка действий: путь проходится на одной строке, с подтверждением клиента перед первым действием, которое что-то меняет на сайте.
- Шаблон `template_actions.py`: таблица на входе, сохранённый вход, `kit.ask` для кода, проверка перед действием, что оно ещё не сделано (повторный запуск не дублирует), `kit.item` по каждой строке, итог.
- Чек-лист: повтор запуска не создаёт дублей; упавшая строка не останавливает остальные, если клиент не просил иначе; данные входа только через `secret`-параметры или `table` с `secret = true`.
- Скилл не учит обходить проверки сайта и маскировать автоматизацию. Проверки сайта браузер DAWG проходит сам, как и раньше.

## 6. Приёмка

Демо-скрипт действий на учебном сайте с формой входа и формами (например, the-internet.herokuapp.com или аналог): таблица из 5 строк, одна заведомо падает, вход сохраняется между запусками, вопрос с кодом, перезапуск упавших. Прогон в UI на macOS, CI на трёх ОС.
