# M6: входы узла, значения по стрелке, проход по строкам

Дополняет `2026-11-17-m6-projects.md`. Решения пользователя: Q34 = C, Q35 = B, Q36 = смешанно, Q38 = да. Наглядно: `.superpowers/brainstorm/67710-1794857012/content/node-inputs.html`.

## Зачем

Скрипт в проекте стартует не только с файлами: ему нужны город, цена, токен, дата. В утверждённом макете редактора на карточке были видны только порты таблиц и файлов, и непонятно, откуда узел берёт остальное. Кроме того, пользователь хочет передавать по стрелке информацию любого формата, а не только файлы, и брать значение из колонки таблицы прошлого узла, с регулировкой того, как обходятся строки.

## Цели

- На карточке узла видны все входы скрипта и откуда у каждого значение: пресет, на узле, стрелка, пусто.
- Стрелку можно провести в любой вход, не только в `table`/`file`.
- Скрипт может отдать одно или несколько значений (токен, номер, цена, список) как свой результат, наравне с файлами.
- Значение входа можно взять из колонки таблицы прошлого узла: первая строка или по разу на каждую строку.
- Обход строк регулируется: какие строки, сколько запусков одновременно, что при падении одного.

## Не цели

- Формулы и выражения на стрелке (склеить строку, посчитать). Это узел-скрипт.
- Обратные стрелки и циклы графа. Проход по строкам это повтор одного узла, а не цикл схемы.
- Вложенный проход (по строкам внутри прохода по строкам).

## Анти-цели

- Узел упал ночью, потому что вход пустой. Незаполненный обязательный вход виден красным на холсте и в `project check`, «Запустить проект» недоступна.
- Проход по строкам незаметно запустил 5000 браузеров. Число строк видно на шаге, одновременность по умолчанию 1, ограничение «первые N» под рукой.

## Подход

Выбран «выходные значения в kit + стрелка в любой вход + режим строк на стрелке».

Отвергнуто:
- Только файлы и таблицы (Q35 A): пользователь хочет передавать информацию любого формата.
- Значение через таблицу из одной строки без нового kit (Q35 C): остаётся как частный случай «колонка, первая строка», но не единственный способ.
- Режим строк только «первая строка» или только «каждая строка» (Q37): пользователь хочет регулировать сам.

## Kit 1.5: выходные значения

- В манифесте `[[outputs]]` получает `kind = "file"` (по умолчанию, как сейчас) или `kind = "value"`. У значения: `name`, `title`, `type` (из типов параметров, кроме `table`, `file`, `secret`), `optional`, `secret` (значение не показывается и не пишется в журнал).
- Скрипт отдаёт значение вызовом `kit.output("token", value)` (точное имя на усмотрение исполнителя). Значение проверяется по типу при вызове. Объявленное и не отданное необязательное значение не ошибка, обязательное даёт `suspicious`, как необъявленный файл.
- Значения хранятся у запуска (экран запуска показывает их в «Результат», секретные скрыты) и доступны как `run:`/`last:` ссылки так же, как файлы.
- Контракт 1.5. Скрипты 1.4 работают как раньше.

## Файл проекта: стрелка во вход

Новый вид соответствия в `files` стрелки (поле можно переименовать в `map`, старое имя читается):

```toml
[[edges]]
from = "login"
to = "orders"
map = [{ value = "token", to = "token" }]          # выходное значение -> вход

[[edges]]
from = "cities"
to = "wb"
map = [{ from = "cities.csv", column = "Город", to = "city", rows = "each" }]
limit = 20                 # необязательно: первые N строк
where = { column = "Активен", op = "eq", value = "да" }   # необязательно, операции как у «Отфильтровать строки»
parallel = 2               # сколько запусков узла одновременно, по умолчанию 1
on_error = "continue"      # continue (по умолчанию) | stop
```

- `{ from, to }` без `column`: файл в `table`/`file`, как сейчас.
- `{ value, to }`: выходное значение в вход. Тип проверяется при сохранении (число в текст можно, текст в число предупреждением, проверка значения при старте шага).
- `{ from, column, to, rows }`: колонка таблицы в вход-значение. `rows = "first"` (по умолчанию) или `"each"`. Для входа-списка (`string_list`, `url_list`, `multi_enum`) есть `rows = "all"`: вся колонка списком.
- `limit` и `where` применяются к таблице до выбора строк, для любого `rows`.
- Секретный вход по стрелке можно заполнить (токен из входа в кабинет); значение не попадает в файл проекта и показывается скрытым.
- Приоритет значения входа: стрелка, затем значение на узле, затем пресет, затем значение по умолчанию манифеста.

## Проход по строкам (`rows = "each"`)

- Узел запускается по разу на каждую выбранную строку. Каждый такой запуск это обычный запуск скрипта, помеченный шагом проекта и номером строки.
- Все соответствия `each` у одного узла должны идти из одной таблицы одного источника (строки берутся парами по номеру). Иначе ошибка проверки при сохранении (решение лида: перемножение таблиц непредсказуемо по числу запусков).
- Одновременно идут не больше `parallel` запусков и не больше `max_parallel_runs` приложения.
- `on_error = "continue"`: остальные строки идут дальше. `stop`: оставшиеся строки не запускаются, идущие доводятся до конца (решение лида: отмена на середине оставляет сайт в неизвестном состоянии).
- Результат шага: файлы с одинаковым именем склеиваются в один (у таблиц добавляется колонка со значением строки, например «Город»), выходные значения собираются в таблицу `values.csv` (по колонке на значение, строка на запуск). Дальше по стрелкам идут как результат одного шага.
- Статус шага: все готово дают «готово»; часть упала при `continue` даёт «частично»; все упали, или `stop` сработал, дают «упал».
- Пустая таблица после `where`/`limit`: шаг «пропущен» с причиной «нет строк».
- «Перезапустить с упавшего» повторяет только строки, которые не дошли до «готово» (решение лида, тем же правилом, что шаги).
- Экран запуска проекта: на узле счётчик «7 из 20, упало 1», список запусков по строкам с переходом к каждому.

## Интерфейс

- Карточка узла (Q34 C): все входы скрипта строками «имя, значение, откуда». Сначала входы со стрелками и пустые обязательные, затем остальные; после 4 строк «ещё N». Секреты показываются точками с пометкой «пресет» или «стрелка».
- У каждого входа слева порт (секретный тоже: токен по стрелке). Порт файла и таблицы и порт значения различаются цветом. Подпись стрелки видна у выбранной стрелки, у входа получателя видно, от какого узла значение. Выходы справа: файлы и значения.
- Выход-таблицу можно развернуть кнопкой «N колонки»: под ней появляется отдельный выход на каждую колонку, и стрелку можно тянуть прямо от колонки во вход. В файле проекта это то же соответствие `{ from, column, to }`, развёрнутость выхода хранится как положение на холсте. Колонки берутся из `outputs.columns`, если не объявлены, из файла последнего запуска узла; если неизвестны, кнопки нет, колонка вписывается в панели стрелки.
- Правка (Q36 смешанно): текст, число, да/нет и выбор правятся на карточке по клику; таблицы, даты, списки и секреты в панели справа.
- Пустой обязательный вход красный, наверху «Узел X: не задан «Город»», «Запустить проект» недоступна.
- Панель стрелки: список соответствий; для колонки выбор колонки (по `outputs.columns`, если объявлены), режим строк сегментом «первая строка / каждая / вся колонка», «первые N», условие, одновременность, «при падении». Без системных выпадающих списков.
- Макет карточки и панели стрелки обновляется до тикета интерфейса и утверждается пользователем.
