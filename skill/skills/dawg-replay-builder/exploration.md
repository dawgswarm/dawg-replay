# Разведка сайта через dawg-mcp

Цель разведки: пройти путь клиента на 1-2 реальных примерах и понять, откуда скрипт возьмёт данные. Каждый открытый браузер тратит минуты DAWG, поэтому браузер держим только на время разведки.

## 1. Браузер

```
browser_provision(geo="moskva")      # для российских сайтов; цены и наличие зависят от города
browser_navigate(url=<страница выдачи или нужная страница>)
```

Запомните `session_id`. Один браузер на разведку.

Если `browser_navigate` падает с `ERR_TUNNEL_CONNECTION_FAILED` на любом сайте, сломан прокси платформы. Освободите браузер и сообщите клиенту, сайт тут ни при чём.

## 2. Антибот

- «Antibot Challenge Page», «Проверяем браузер» и подобное: JS-проверка, проходит сама за несколько секунд. Ждите по признаку: `browser_wait_for(text_gone="Проверяем браузер")`. В скрипте то же самое делает `wait_ready` из `template.py`.
- Слайдер-капча («Сопоставьте пазл») или другая капча: не обходить. Освободите браузер, попробуйте позже или с другим `geo`. Если капча повторяется, сообщите клиенту и предложите другой источник или урезанный набор полей.
- Капча может быть только на части страниц. На Ozon выдача открывается, страница товара сразу даёт слайдер, и после этого браузер получает капчу и на выдаче. Открывайте такие страницы последними или не открывайте вовсе.

## 3. Где лежат данные

Порядок предпочтения: внутренний JSON-API, данные в самой странице, DOM.

Какие запросы делает страница:

```js
() => performance.getEntriesByType("resource").map(e => e.name)
  .filter(u => /api|search|catalog|json/i.test(u) && !/\.(js|css|png|jpe?g|webp|svg|woff2?)(\?|$)/.test(u))
```

Данные в странице:

```js
() => ({
  next: !!document.getElementById("__NEXT_DATA__"),
  nuxt: typeof window.__NUXT__ !== "undefined",
  ldjson: document.querySelectorAll('script[type="application/ld+json"]').length,
  states: [...document.querySelectorAll("[data-state]")].map(e => e.id).slice(0, 30),
})
```

Тело ответа API надёжнее всего смотреть коротким скриптом-зондом на kit: он открывает страницу, сохраняет ответы и прокручивает выдачу. Запускайте его автономно (`uv run probe.py`), ключ в `DAWG_API_KEY`:

```python
# /// script
# requires-python = ">=3.10"
# dependencies = ["dawg-replay-kit>=1.1,<2", "dawg-sdk-python>=0.4,<0.5", "playwright>=1.58,<2"]
# ///

# /// dawg-script
# contract = 1
# name = "probe"
# title = "Разведка"
# version = 1
# ///
import json, time
import dawg_replay_kit as kit

URL = "https://..."  # страница выдачи
MARK = "/api/"       # часть адреса нужных запросов

with kit.browser(geo="moskva") as b:
    seen = []
    def keep(r):
        if MARK not in r.url or "json" not in r.headers.get("content-type", ""):
            return
        try:
            body = r.body()
        except Exception:
            return  # ответ пришёл, когда браузер уже закрывался
        n = len(seen)
        (kit.output_dir / f"resp{n}.json").write_bytes(body)
        seen.append({"n": n, "url": r.url, "status": r.status})
    b.page.on("response", keep)
    b.page.goto(URL, timeout=90000)
    time.sleep(5)
    for _ in range(10):
        b.page.mouse.wheel(0, 4000)
        time.sleep(1)
    (kit.output_dir / "seen.json").write_text(json.dumps(seen, ensure_ascii=False, indent=1))
kit.result("ok", f"ответов: {len(seen)}")
```

Браузер зонда kit закрывает сам. Быстрая попытка без скрипта: подменить `window.fetch` через `browser_evaluate` и прокрутить страницу. Многие сайты берут ссылку на `fetch` при загрузке, и подмена их запросов не видит (так на Ozon), поэтому пустой результат ничего не значит.

Прямой `fetch` к внутреннему API со страницы часто получает 403: на WB и Ozon антибот ждёт заголовки, которые ставит сама страница. В скрипте перехватывайте ответы самой страницы: `page.expect_response` для первой загрузки и `page.on("response")` для остальных, как в `template.py`. Заголовки подделывать не нужно.

## 4. Пагинация и подгрузка

- Номер страницы в адресе (`?page=2`): проверьте, что сайт его уважает. На WB `&page=2` в адресе выдачи игнорируется, вторая страница приходит только прокруткой.
- Бесконечная лента: прокрутите и посмотрите, какой запрос ушёл и с каким номером. Скрипт крутит, пока не придёт ответ с нужным номером (`scroll_until`).
- Размер страницы задаёт сайт и может меняться: на Ozon встречалось 8 и 36 карточек. Параметр скрипта считает страницы.
- Где конец: пустой список, меньше карточек, чем обычно, или поле `total` в ответе.

## 5. Адреса, сортировка, редиректы

- Поиск может перенаправить на другой адрес: Ozon уводит запрос в категорию с тем же `text`. Скрипт открывает адрес поиска и ждёт данные, конечный адрес не важен.
- Значения сортировки и фильтров берите из ссылок самого сайта (виджет сортировки), не угадывайте.
- Лишние параметры ссылок (метки отслеживания вроде `?at=...`) из ссылок на карточки убирайте.

## 6. Поля

- Для каждого поля, которое просил клиент, найдите его в данных. Цены в API бывают в копейках.
- Проверьте похожие значения: на Ozon «4.5 рейтинг магазина» стоит на месте рейтинга товара у карточек без отзывов.
- Если поля нет в выдаче, а детальная страница закрыта капчей, согласуйте с клиентом набор полей и напишите об этом в описании скрипта.
- Сверьте 2-3 карточки руками с тем, что видно на странице.

## 7. Записать находки

В шапку скрипта (docstring после манифеста): дата разведки, адрес выдачи, эндпоинт или элемент с данными, пагинация, размер страницы, что делает антибот, нужен ли `geo`, каких полей нет и почему.

## 8. Освободить браузер

Сразу после разведки, до того как писать код:

```
browser_release(session_id=<ваш>)
browser_list_sessions()
```

В `account_sessions` могут быть браузеры клиента и других программ на том же ключе. Освобождайте только свои.
