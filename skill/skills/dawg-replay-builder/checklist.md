# Проверки перед `dawg-replay add`

Каждый пункт проверяется по факту: по коду, по событиям запуска, по файлу результата. Пункт не выполнен: исправь и прогони проверку заново.

## Манифест и параметры

- [ ] Черновик лежит в `./<name>/script.py`, `<name>` совпадает с `name` в манифесте; чужие черновики в других папках не тронуты.
- [ ] `dawg-replay validate <name>/script.py` без ошибок.
- [ ] Всё, что клиент назвал изменяемым (запрос, город, категория, объём, сортировка, фильтры), вынесено в параметры с понятными `title`; у необязательных есть `default`.
- [ ] `contract = "1.1"` (с параметрами `date`, `table` или `kit.browser(login=...)`: `"1.2"`; с `multi_enum`, `time`, `datetime`, подписями вариантов или относительной датой в `default`: `"1.3"`); `site` назван так, как сайт называет клиент (`"Ozon"`, `"Яндекс Маркет"`), в `tags` 1-3 короткие метки о том, что собирается (`"Цены"`, `"Отзывы"`), без повторов.
- [ ] Для починки: `name` прежний, `version` больше текущей (`dawg-replay versions <name>`); черновик взят из текущей версии (`dawg-replay show <name>`), отличия старого черновика согласованы с клиентом.
- [ ] Токены внешних сервисов только в параметрах `secret`; в коде, `default` и комментариях их нет.

## Код

- [ ] В коде нет значений из разведки: конкретного запроса, id, URL с параметрами поиска, cookies, токенов, `session_id`, CDP-адресов. Ищи глазами строки, скопированные из браузера.
- [ ] Данные берутся из API или данных в странице, если они есть; селекторы, если без них нельзя, устойчивые (роли, `data-*`, тексты), без позиционных (`nth-child`, длинных цепочек `div > div`).
- [ ] Браузер открывается только через `kit.browser()`, лимит задан явно: `kit.set_browser_limit(n)`.
- [ ] У сетевых ожиданий явные таймауты; временные сбои повторяются с паузой; темп запросов умеренный.
- [ ] Проверка сайта ждётся по признаку на странице с таймаутом; не прошла: понятная ошибка в `kit.log.error` («сайт не пропустил браузер...») и `result: failed` или `partial`; повторов ограниченное число.
- [ ] `kit.progress` идёт по согласованной с клиентом единице; есть 1-3 `kit.metric`; `kit.rows` даёт превью.
- [ ] Результат пишется в файл в `kit.output_dir` по ходу работы (после каждой страницы или пачки), файл отдан через `kit.artifact`.
- [ ] Падение на середине: собранное сохранено, в конце `kit.result("partial", ...)` с причиной.
- [ ] В шапке скрипта комментарий: источник данных, находки разведки (эндпоинты, особенности), дата.

## Проверочный запуск

- [ ] `dawg-replay run <name>/script.py --set <объём>=1 ... --json --follow` закончился `ok` (или ожидаемым `partial` с понятной причиной).
- [ ] `dawg-replay logs <run_id> --events`: есть `progress`, `rows`, `artifact`, `result`; ошибок и предупреждений без причины нет.
- [ ] Файл в `<run_dir>/output/` открыт: колонки те, что просил клиент, значения не пустые, 3 строки сверены с сайтом (название, цена, ссылка).
- [ ] Запуск с другими значениями параметров (другой запрос или город) тоже даёт правильные данные.
- [ ] После запусков нет предупреждения «возможно, остался браузер» (`dawg-replay runs --json`, поле `suspects`), браузеры `dawg-mcp` освобождены (`browser_list_sessions` пуст для твоих сессий).

## Действия (раздел B)

- [ ] Вход только через таблицу с `secret = true` или параметры `secret`; паролей и кодов нет в коде, `default`, событиях, ключах и сообщениях `kit.item`.
- [ ] Вход через `kit.browser(login=...)`, скрипт сам проверяет, что вошёл, и входит заново, если сохранённый вход устарел.
- [ ] Код из SMS или письма спрашивается через `kit.ask(..., secret=True)` с разумным `timeout_minutes`; `AskTimeout` даёт `failed` у строки, а не падение всего запуска.
- [ ] Перед первым изменением на сайте `kit.ask(..., kind="confirm")`, если клиент не отказался от подтверждения.
- [ ] Перед действием проверка «уже сделано»: повторный запуск на той же строке дал `skipped`, дубля на сайте нет.
- [ ] После действия сверка по сайту (обновить страницу, найти результат), а не только сообщение «сохранено».
- [ ] Упавшая строка не останавливает остальные: проверено запуском со строкой с неверными данными; у неё `failed` и понятное сообщение.
- [ ] `columns` у параметра `table` перечисляют все нужные колонки: по ним форма строит ввод строк руками и проверяет файл; клиенту рассказано про файл, пресет (секретную таблицу тоже) и ввод строк руками.
- [ ] `kit.item` на каждую строку с `row=row["_row"]` (отчёт по строкам и CSV строит приложение, свой `report.csv` не нужен), итог `ok`, `partial` или `failed` по числу упавших строк.
- [ ] Есть режим без изменений (`check_only` или похожий), им проверено, что скрипт находит строки, которые нужно сделать.
- [ ] Скрипт не обходит проверки сайта и не маскирует автоматизацию; действует только в кабинетах клиента.
- [ ] Таблица на разведке и в проверочных запусках маленькая (1-2 строки), изменения на сайте согласованы с клиентом.

## Клиенту

- [ ] После `dawg-replay add` клиент знает: как открыть `dawg-replay ui`, что значит каждый параметр, где скачать результат, что сказать агенту, если скрипт сломается; что приложение хранит свою копию и черновик `./<name>/script.py` (полный путь) можно удалить.
