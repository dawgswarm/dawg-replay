# dawg-replay-builder

Ты один раз проходишь путь по сайту через браузер DAWG (`dawg-mcp`) и превращаешь его в скрипт `script.py` по контракту `dawg-replay`. Дальше скрипт работает без тебя: клиент запускает его в приложении, меняет параметры и платит только минутами DAWG.

Справочные файлы рядом:

| Файл | Когда читать |
|---|---|
| [contract.md](contract.md) | форма скрипта, типы параметров, события, браузеры; перед сборкой |
| [exploration.md](exploration.md) | как разведывать сайт через `dawg-mcp`; перед разведкой |
| [template.py](template.py) | эталонный скрипт; основа для сборки |
| [checklist.md](checklist.md) | проверки перед `dawg-replay add`; обязательно |

## 0. Проверка окружения (всегда первым шагом)

1. Инструменты браузера DAWG: среди твоих инструментов есть `browser_provision`, `browser_navigate`, `browser_snapshot`, `browser_release` с любым префиксом сервера (`mcp__dawg__browser_provision`, `mcp__plugin_..._dawg__browser_provision` и так далее). Нет таких инструментов: `dawg-mcp` не подключён.
2. Приложение: `dawg-replay --version --json`. В `contracts` должна быть `1`. Команда не найдена или `1` нет: приложение не установлено или старое.
3. Ключ: `dawg-replay --json config show`, поле `api_key_set`. `false`: попроси клиента выполнить `dawg-replay config set-key` (или ввести ключ в UI на экране Настройки). Ключ сам не вводи и не проси прислать его в чат.

Если 1 или 2 не выполнены, объясни клиенту, что поставить, и дальше не иди:

- `dawg-replay`: `uv tool install dawg-replay`, нужен `uv` (https://docs.astral.sh/uv/) и Python 3.10+.
- `dawg-mcp` в Claude Code: плагин `dawg-replay-builder` подключает его сам; вручную `claude mcp add dawg --scope user --env DAWG_API_KEY=<ключ> -- uvx dawg-mcp`. В Codex: блок `[mcp_servers.dawg]` в `~/.codex/config.toml` (см. README плагина). После подключения перезапусти сессию.

## A. Новый скрипт

1. **Разговор, коротко.** Узнай: что собрать и откуда, какие поля, что клиент будет менять между запусками (это параметры), что считать единицей прогресса (страница, карточка), примерный объём, куда отдавать данные (CSV по умолчанию; внешний сервис означает параметр `secret`). Не больше 2-3 вопросов за раз; очевидное выбери сам и скажи, что выбрал. Расписаний в приложении нет: на «каждый день» скажи это прямо; клиент запускает сам (кнопка в UI или `dawg-replay run <name> --preset <пресет>`, его можно поставить в cron).
2. **Разведка** по [exploration.md](exploration.md). Пройди весь путь на 1-2 реальных примерах. Сначала ищи внутренний JSON-API в сетевых ответах и данные в странице (`__NEXT_DATA__`, `data-state` и подобное), DOM только если их нет. Выясни пагинацию, ленивую подгрузку, антибот, нужен ли `geo` или прокси. Запиши находки: эндпоинты, параметры запросов, селекторы, особенности.
3. **Сразу после разведки освободи браузер**: `browser_release` (и проверь `browser_list_sessions`). Код пишешь без открытого браузера: он тратит минуты клиента. Понадобилось уточнить: открой новый, уточни, освободи.
4. **Сборка** на основе [template.py](template.py) по [contract.md](contract.md): всё изменяемое в параметрах манифеста, браузер только через `kit.browser()` и `kit.set_browser_limit(n)`, повторы с паузами и таймауты, `kit.progress`, `kit.metric`, `kit.rows`, файл через `kit.artifact`, в конце `kit.result`. Собранное пишется в файл по ходу работы; падение на середине даёт `result: partial`. В шапке комментарий: откуда данные, что нашла разведка, дата.
5. **Проверка**:
   - `dawg-replay validate script.py`;
   - `dawg-replay run script.py --set <параметр объёма>=1 --set ... --json --follow` (например `max_pages=1`): самый маленький прогон; в ответе `run.id`, `run.status`, `run_dir`;
   - `dawg-replay logs <run_id> --events` и файлы в `<run_dir>/output/`: открой CSV и сверь 3 строки с сайтом. Код выхода 0 и `ok` ничего не доказывают: проверяешь данные;
   - не сошлось: правь и повторяй. Затем пройди [checklist.md](checklist.md).
6. **Регистрация**: `dawg-replay add script.py`. Скажи клиенту простыми словами: `dawg-replay ui` откроет приложение в браузере, на экране «Скрипты» его скрипт, на экране скрипта форма; что значит каждый параметр, сколько примерно идёт запуск, где скачать результат, что делать, если сайт сменится (прийти к тебе с фразой «скрипт сломался»).

## C. Скрипт сломался

1. `dawg-replay runs <name> --json`: найди упавший запуск.
2. `dawg-replay logs <run_id> --events` (и без `--events` для stderr): где именно и почему.
3. Пройди это место заново через `dawg-mcp`, затем `browser_release`.
4. Правь **тот же файл** скрипта (`dawg-replay show <name>` покажет путь текущей версии; скопируй его к себе), подними `version` на 1, проверь по шагу A.5 и [checklist.md](checklist.md), `dawg-replay add`.
5. Новый скрипт с нуля только если клиент сам попросил.

Причина не в коде (кончились минуты, неверный ключ, лимит браузеров тарифа, сайт закрыт капчей): скажи клиенту как есть и не правь скрипт ради обхода.

## Запреты

| Нельзя | Почему | Как надо |
|---|---|---|
| Оставлять в коде значения из разведки: запрос, город, id категории, конкретные URL с параметрами поиска, cookies, токены из сетевых ответов | скрипт работает только для того примера, клиент не может ничего поменять | параметр манифеста с `default`; токены и cookies скрипт получает сам при каждом запуске |
| Зависеть от сессии MCP: `session_id`, CDP-адрес, открытая вкладка, ручной шаг агента | после твоего ухода скрипт падает | скрипт сам открывает браузер через `kit.browser()` |
| Обходить капчу, слайдер-капчу, антибот подделкой заголовков, решателями, перебором выходов | нарушение правил сайта и риск для аккаунта клиента | сообщить клиенту; в скрипте понятная ошибка «сайт показал капчу» |
| Держать браузер `dawg-mcp` открытым после разведки | клиент платит за минуты простоя | `browser_release` сразу после разведки |
| Считать скрипт готовым по коду выхода 0 | пустые или чужие данные тоже дают 0 | сверить строки CSV с сайтом |
| Писать новый скрипт вместо починки | теряются версии и пресеты клиента | тот же `name`, `version + 1` |

## Красные флаги: остановись

- В коде строка, которую ты скопировал из адресной строки или из ответа сервера во время разведки.
- «Сейчас быстро допишу, браузер пока пусть висит».
- «Капча редкая, добавлю ретраи, пока не пропустит».
- «Запуск `ok`, значит работает» без открытого CSV.
